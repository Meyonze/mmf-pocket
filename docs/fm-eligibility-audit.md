# 演奏中のFM適用対象と側帯波の診断

`tools/fm-eligibility-audit.cpp`は、実際に音源を進めて、帯域制限の試作対象に入るFMの
同時発音数・チャンネル数・生存時間を調べます。本体・公開版・キャッシュは変更しません。
静的な音色定義だけを数える[tone-usage-audit](fallback-balance-profile.md)とは用途が異なります。

## 観測する範囲

対象はフィードバックのない直列2正弦波です。4演算器・加算・非正弦波・フィードバックは
対象外の理由を分けます。この主集計は従来の範囲を維持しています。並列4演算器の候補と
その倍率は別項目で集計し、従来の理由別件数では`four_operator`にも含まれます。別に、フィードバックなしの正弦波だけで構成される各接続の
生存時間も数え、次に拡張する候補を調べます。未使用演算器の設定は接続の分類に使いません。

各フレームで、その時刻の命令を通常どおり適用した後、音源を進める前に観測します。
短い音や同じ時刻の発音枠の置換を、粗い間隔のサンプリングで見落とさない方式です。
通常の公開`render()`で別に進めた出力と、全サンプルのfloatビット列・長さ・終了状態・
発音と置換の件数を照合してからレポートを出します。比較用のPCMは固定長のバッファーだけに保持します。

無音の音量設定であっても、将来のコントローラーで復帰する声は対象の生存時間に含めます。
その時点の抑制状態と、解放中・LFO付きの時間は別の項目です。埋め込みPCM・録音・独立したATRは
ネイティブ音源として別に数えます。出力には入力名・曲名・作者・楽器名は含めません。

## 定常2正弦波の倍率の目安

この目安は、実機音源や聴感の評価、動的なEG・LFO・ゲート・有限FIRの誤差の保証ではありません。
音量や音色を変更するルールとしては使っていません。

変調指数の上限を、実際の音源の変調深度と変調器のTL・キー音量から求めます。
EGとAMの振幅は最大1で見積もります。発音中の声であっても、変調器の停止アタックや終了が
確定している場合は変調をゼロとします。音量の閾値ではありません。

整数k・実数xに対する`|J_k(x)| <= (|x|/2)^k / k!`から、両側の側帯波係数の残りを
幾何級数で上から抑えます。残りのL1上限が1e-5以下になる次数Nを求め、
`carrier_upper + N * modulator_upper < factor / 2`となる倍率を1／2／4／8／16／32から探します。
周波数はネイティブレートに対する比率です。超える場合は`beyond32`として扱い、32へ丸めません。

ビブラートは現在のコントローラー設定で取り得る瞬時周波数の上限を使います。
それだけで、時間変化する波形の全スペクトルを有限帯域とみなすことはできません。
LFO付きの件数を別に示すのはそのためです。途中で倍率を変える指定にもしていません。

## 実行と制限

```sh
mkdir -p build/fm-eligibility-audit
c++ -std=c++20 -O2 -Ithird_party/yamaha-smaf-player/src tools/fm-eligibility-audit.cpp build/native-render/libsmaf.a -o build/fm-eligibility-audit/audit
build/fm-eligibility-audit/audit original.mmf 15 > build/fm-eligibility-audit/report.json
```

入力は最大16MiB、観測は最大600秒です。上限に達した場合は`cap_reached`を示し、
未完了のファイルを全体の調査済みとは扱いません。スコアの読み取り完了、音源の安全な末尾制限も
それぞれ`scan_complete`・`tail_limit`で確認します。入力ファイルやアプリ設定を書き換えません。

C++の専用テストは、Bessel係数の数値との照合、分類、単一フレームの発音、40音の同時発音と8枠の置換、
Hold、音量ゼロからの復帰、音程変更、同じ時刻の停止とNoteOn、上限ちょうどの命令、EOFを確認します。
CLIの9テストは、JSONの集計、非公開情報を含めないこと、高い変調での倍率分類、実ファイルの40音と置換、入力と時間の境界を確認します。
Release O2とASan/UBSanで通っています。

## 自作素材の調査結果

個人の楽曲ではなく、既存のバランス確認280素材とFM確認34素材を調べました。
314素材すべてで、通常の出力とのビット一致と、読み取り・演奏の完了を確認しました。
直列2正弦波の対象に入ったのは66素材ですが、今回の定常モデルではすべて倍率1の範囲でした。
これらは低い音域の単音素材が中心で、実曲の発音数や高音域を代表するものではありません。

高い音域の強い位相変調を、1／8／32／40音で鳴らす自作素材も追加して計318素材を確認しました。
追加4素材では16倍・32倍の分類が現れ、最大32音・16チャンネルの同時発音を観測しました。
40音では通常の音源と同じ8枠の置換も確認しました。これらの数値だけで、
その倍率を端末で常時実行できるとは判断しません。

既存の素材には、フィードバックなしの正弦波4演算器で、2本の2演算器を並列にする接続もありました。
この[並列接続の試作](fm-parallel-pair-prototype.md)も追加し、直列2演算器の集計を維持しつつ、
並列候補の生存時間・定常モデルの倍率を別項目で測っています。音程・発音数・固定倍率の選択を詰めます。
内蔵ROMの近似音色の音量校正や、資料のない動作の推測による変更は行いません。

高音域・多重発音の素材は、`python3 tools/generate-fm-load-probes.py build/fm-load-probes`で
新しい出力フォルダへ再生成できます。楽曲やROM波形は含めません。
