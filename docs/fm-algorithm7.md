# r84：FM接続7の折り返し低減

通常再生の8倍・Hermite処理を、正弦波4演算器の接続7へ広げます。この接続は
`op0 + (op1 → op2) + op3`で、元の0.4倍の混合係数を保持します。
4演算器すべてが正弦波で、実効フィードバックがない場合だけ適用します。
独立した二本の音と変調される枝を同じ時刻で合成し、既存のFIRへ渡します。
キャッシュはr84へ更新します。正式版の公開・バージョン更新は行っていません。

ネイティブAPIの既定は従来方式を維持します。追加サンプル生成も元のtickを一度だけ実行し、
そのサンプルを終点に残します。位相・EG・LFO・Hold・発音枠の判断は元の速度を保ちます。
既存の接続0/5のサブサンプル式と混合係数は維持し、接続3/4/6やフィードバックは対象外です。

## 数式と実出力の照合

`tools/fm-algorithm7-test.cpp`は、公開プレイヤーに独自のVM5設定と譜面を渡します。
変調される枝を独立したBessel側帯波計算、二本の直接出力を正弦波の解析式で表し、
既存の0.4、出力ローパス、有限FIRの複素応答を別計算します。内部パラメーターの読み戻しは
数式基準に使いません。音程60/72/84/96、二つの周波数倍率、三つの変調器TLについて、
通常・遅延対照・2/4/8/16/32倍のExact/Hermite、計288設定を照合しました。
最大RMS誤差は約3.23e-8でした。

音程84、キャリア5・変調器7・TL0の例では、理想帯域とのRMS誤差が通常約0.08179から
8倍・Hermiteで約4.04e-6へ低下しました。これは自作の定常音色の結果であり、
実曲の聴感や旧端末の再現度の測定ではありません。強い変調や高い音では8倍で残る成分もあり、
音量の補正・正規化は加えません。

## 時刻・混在・アプリ経路

240条件で元のnative tickと終点ビット値、位相、EG/Hold、LFO、発音状態、recentLevelを
比較しました。ゲインゼロからの復帰、微小音、MA7の低位アタック、Nyquistをまたぐ音程変更を
含みます。各演算器の非正弦波またはフィードバックを使う8対照は、出力や時刻を変えずに拒否します。
公開APIの時計検査は180条件へ拡張し、PCM・独立ATRとの寄与検査でも接続7を含めています。

32の実ファイル比較では対象24素材のアプリ出力が明示8倍処理と一致し、対象外8素材はr83と
WAV全体が一致しました。以前のアプリ比較10素材もr83と一致しています。
通常の2,121素材のWAVは、ネイティブAPIの既定経路で従来と完全一致しました。
ReleaseとASan/UBSanの新規検査、既存の公開API・ゼロ復帰・実プレイヤー・曲末・
パート寄与・実JNI/WAV検査が通過しています。Android全ABIのDebug/ReleaseビルドとLintも成功しました。

既存接続0/5の960条件・2,285,568サブサンプルと状態を変更前後のバイナリ記録で比較し、
完全一致しました（途中サンプルの符号付きゼロだけは従来の比較形式に合わせて正規化）。
