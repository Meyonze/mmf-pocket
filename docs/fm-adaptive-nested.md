# 強い直列FMの選択的な高倍率処理

固定16/32/64/128倍の実MMF経路に続き、対象音の周波数から倍率を選ぶ実験経路を追加しました。
通常のアプリ初期化、キャッシュr91、正式版1.6.6は維持しています。

```sh
smaf-render input.mmf output.wav 30 --experimental-adaptive-nested
render-contribution-audit input.mmf 30 --experimental-adaptive-nested
```

C++では`SineRenderOptions{8, FmSubframeMath::Hermite, true, false, true}`です。
フラグ単体で方式を指定し、固定倍率・数式方式・固定nested・app-qualityとの併用と重複は拒否します。
寄与診断は`adaptive_nested: true`と32/64/128倍を含むカウンターを出し、実レンダラーと照合します。
既存のレポートの形式は維持します。

## 初期対象と倍率

従来の8/16倍方針を先に維持します。新たに加えるのはmodern VM35の4演算器・接続6、
全正弦波、実効フィードバック・固定周波数・MA7 Detuneなし、両変調器のTLが12以上、
演算器1/2/3の設定上のアタックが非ゼロ、実効ビブラートなしの音です。
従来対象の弱いVM35、MA7、他の接続や対象外の音は従来経路へ残します。
これは端末間の音色互換性を確定する分類ではありません。

新しい対象では、演算器の最大周波数を出力サンプルレートで割った値qに対して、
q<=0.05で16倍、q<=0.1で32倍、q<=0.2で64倍、それ以上で128倍を選びます。
既存のnative Nyquist抑制を保ち、0.5以上の演算器はそのまま抑制します。
同じ発音中の倍率は上昇だけに限定し、再発音で初期化します。ピッチ変更は次のフレームから反映します。
通常のプレイヤーが生成する有限・非負のピッチが前提です。公開コアAPIへの不正なピッチは品質保証の対象外です。

TL12のVM35変調指数は約8.918で、定常上限を両変調器とも9として検証しています。
独立周波数の解析的な絶対係数和の上限をfactor-0.5で計算すると、上記4閾値でそれぞれ
約3.04e-10、1.16e-10、7.48e-11、4.14e-6となり、1e-4以下に収まります。
重い探索をレンダリング中に実行せず、対象の判定と周波数比較だけを使います。
この定常上限はEG・コントローラーの過渡やFIR後の全誤差を保証するものではありません。

## 履歴と検証

従来の8/16倍バスに加え、実験時だけ32/64/128倍バスを初期化します。
すべて72フレームの遅延へ揃え、音が移った旧バスはゼロ入力で余韻を出し切ります。
PCM・ATR・録音Audioは一度だけnative遅延へ通します。曲末は全バスの有限余韻と既存LPを待ち、
ハード上限は従来どおり72フレームを加えた境界でフェードします。
通常経路の32要素の作業領域は維持し、大きな作業領域は実験用のテンプレート実体だけが使います。

実プレイヤーの16→32→64→128倍、下降ピッチ、余韻の重なる再発音、音量ゼロと微小音量からの復帰、
Holdと解放を、別実装の音源と密なFIR畳み込みで照合しています。
曲末・1/17/1024フレームのブロック・シーク・再初期化・不正初期化の原子性・3種類のハード上限、
4倍率同時発音とPCM/ATR混在の寄与診断も検査します。
24種類の既存ファミリー・接続の出力は従来方針とビット一致しました。
自作MMFの4音程では、選択された倍率の固定モードと実WAVが完全一致しました。

## 残ること

高倍率の多重発音はまだ重く、端末上の速度・電力は未測定です。
今回の閾値も保守的な初期設定です。ビブラートを含む範囲の拡張、過渡での実質的な折り返し量、
実ファイルの音色バランスと端末音源との比較を続けてから、通常アプリへの適用を判断します。
EOFやフィルターの履歴が正しいことと、聴感上の完全な再現は別の検証です。
