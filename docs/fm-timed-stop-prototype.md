# 遅延中の停止と再発音を分ける試作

[チャンネル別履歴](fm-channel-prototype.md)に続く、ホスト専用のタイミング実験です。
`tools/fm-timed-stop-prototype.h`を追加しました。アプリの再生エンジン、公開版1.6.6、
変換キャッシュr82は変更しません。

## 今回試した停止方針

音源の入力フレームnで強制停止したとき、その停止を共通群遅延の72フレーム後に反映します。
停止前の入力の寄与だけを除き、停止時刻以降に再発音した音は残します。
これは明示的なハードカットの候補であり、メーカー実機の停止方式を確認したものではありません。
本体の既存AllSoundOffは共有フィルターの履歴を保つため、そのまま同じ動作ではありません。

| 処理境界 | 試作の動作 |
| --- | --- |
| 音源入力n | 呼び出し側が対象の声を停止し、強制停止のフラグを渡す |
| nからn+71 | それまでの再生履歴を保持。新しい入力も蓄積 |
| n+72 | 入力nより前の寄与を除去。入力n以降の新しい音は保持 |

同じ入力フレームで「停止→NoteOn」の順に処理された場合、新しい音を残します。
「NoteOn→停止」なら呼び出し側でその声も止め、対応する入力をゼロにします。
通常のNoteOffやHoldは音源側の解放処理を使い、強制停止フラグを立てません。
他チャンネルや独立したATRの音源を止める処理は含みません。

## 近接する停止だけを直接計算

通常は従来のストリーミングFIRを使い、単発の停止時に73フレームを再構成します。
受信済みの命令に4フレーム以内の次の停止反映がある場合は、同じ有限FIRの係数から、
停止前の項を除いた現在の出力だけを直接計算します。近接した停止の列の最後で、
一度だけ73フレームを再構成し、通常処理へ戻します。

これは計算経路の切り替えです。次の停止を早く適用したり、停止命令をまとめて捨てたりはしません。
未受信の音声や命令も読みません。通常の72フレーム遅延の中に保持済みの命令を使います。
通常のNoteOff・Hold・音量や音程の更新をまとめる処理ではありません。

FMサブサンプルとPCMの入力履歴は77フレームの固定長です。直接計算に必要な
カスケードFIR係数も開始時に準備するため、従来案より固定メモリーは増えます。
フレーム処理中に確保したり、停止回数に比例して履歴を増やしたりはしません。
直接計算中も、停止時刻、余韻の処理上限、シーク時の命令取り消しを保ちます。

保持中の入力がすべて無音の区間は、正確なゼロ判定で不要な積和を省きます。
音量閾値は使わず、1e-100のFM・PCMも保持します。

`pendingFrames()`は音声だけでなく、遅延中の停止命令も含む処理上限です。
この値だけで公開WAVの長さを決める設計にはしていません。
全体リセットは音声履歴と未反映の停止命令を両方消します。

## 検証

Release O2とASan/UBSanの専用テストが通っています。

- 2／4／8／16／32倍、停止なし・単発・連続・2〜5フレーム間隔・不規則な停止、4種類の処理区間。
  129,600出力を、停止時刻より前の項を除いた独立した密な畳み込みと照合。
  前回の再構成方式も`tools/fm-replay-stop-reference.h`に固定して、出力と余韻・命令の残り時間を照合。
- 停止なしの場合は、既存の`AlignedBus`と出力が完全一致。
- PCMの停止は正確にn+72で反映し、翌フレームの1e-100の再発音も保持。
- 実FMのHold中の停止、連続停止、同一フレームと直後のNoteOn、PCM混在を確認。
- EOF・命令だけが残る区間・シークでの命令取り消し、不正入力拒否で時刻が進まないことを確認。
- 1〜4フレーム間隔の停止列では最後に一度だけ再構成し、疎な停止では従来の計算経路を維持。
- 無音の停止列からの極小FM・PCMの復帰、直接計算から通常処理への復帰を照合。
- 保持する入力は77フレームの固定長で、停止回数では増えないことを確認。

## 負荷と残る課題

共有ホストで、1チャンネル・4,096フレームのバス部分を5回ずつ交互の順番で測ります。
FM合成、初期化・カーネル準備、ファイル入出力、Androidの再生経路は含みません。
短時間の測定なので変動があります。停止間隔は0（停止なし）／256／1〜5フレームです。

```sh
c++ -std=c++20 -O2 tools/fm-timed-stop-cost.cpp -o build/fm-timed-stop-prototype/cost
build/fm-timed-stop-prototype/cost > build/fm-timed-stop-prototype/cost.json
```

時間比は候補／従来の各実行ペアの比率の中央値です。1より小さいほど短時間です。

| 停止間隔 | 8倍 | 32倍 |
| --- | --- | --- |
| 停止なし | 0.925 | 1.027 |
| 256フレーム | 1.001 | 1.045 |
| 1フレーム | 0.037 | 0.054 |
| 2フレーム | 0.085 | 0.105 |
| 3フレーム | 0.122 | 0.169 |
| 4フレーム | 0.174 | 0.212 |
| 5フレーム | 1.146 | 0.917 |

毎フレーム停止の条件は、ペア時間比で約1/18〜1/27でした。停止なし・疎な停止では
実行順序やホスト負荷によるばらつきがあり、速度維持・向上は断定しません。

多数のチャンネル、異なる命令密度、端末での負荷は別の確認が必要です。
5フレーム以上離れた停止では従来の再構成を使うため、そうした区間の負荷問題が
すべて解消したわけではありません。追加の固定メモリーと初期化コストも評価が必要です。

採用する停止方針、音色ごとの適用条件と倍率、倍率変更、WAVの先頭・末尾と時刻表示、
4演算器・フィードバック・非正弦波、端末負荷も引き続き確認します。
本体へはまだ適用していません。
