# 明示的に選ぶFM追加サンプルの再生経路

[音源API](fm-core-subframes.md)を`MaPlayer`の実際のイベント処理・ミックスへ接続しました。
ネイティブAPIとホストCLIの既定は従来経路です。作業版アプリはr83から、通常再生・WAV変換に
8倍・Hermiteを指定します。対象外の音源は従来の合成と共通遅延を使います。
正式版1.6.6への公開はまだ行っていません。[アプリへの適用範囲](app-fm-quality-r83.md)を参照してください。

## 設定

```cpp
MaPlayer player;
player.init(file, 44100, false, {8, FmSubframeMath::Hermite});
// player.renderLatencySamples() == 72
```

`SineRenderOptions`の`factor`は次の意味です。

| 値 | 経路 |
| --- | --- |
| 0・省略 | 従来の再生処理 |
| 1 | 全音源を72フレーム遅らせる比較用の経路 |
| 2・4・8・16・32 | 対象FMを追加サンプルと因果FIRで処理し、その他の音源も共通遅延に合わせる |

方式は`Exact`が既定で、`Hermite`は途中の正弦波だけを軽量な補間に置き換えます。
倍率と方式は`init`で決め、シークでも保ちます。通常経路へ戻す場合は設定なしで再初期化します。
適用対象は正弦波の直列2演算器・接続0、または並列4演算器・接続5で、実効フィードバックが0の場合です。
他のFM、WT・PCM、録音Audio、独立ATRは元の速度で合成します。音量・パンは入力時刻の値を使い、
全音源が揃ってから既存のローパスとリミッターへ渡します。

これは倍率を指定する実験用の経路です。全音色に最適な倍率の自動選択や、端末上の速度の保証は
行っていません。高い変調では32倍でも残る折り返しがあり、除いた成分の電力を補う音量補正は加えません。

## 遅延・停止・曲末

共通の群遅延は72フレーム（44.1kHzで約1.63ms）です。FIRの末尾上限は倍率ごとに
136・140・142・143・144フレームです。PCM等には72フレームのFIFOを使います。
フィルターの係数は全プレイヤー・左右で共有し、可変の履歴は各プレイヤーで独立します。
係数と補間テーブルは有効な`init`時に準備し、バスのフレーム処理でメモリーを確保しません。

AllSoundOffや発音枠の置換では、対象の新しい入力だけを止めます。共有FIR・ローパス・
リミッターの履歴を保ち、他パートやATRへ干渉しません。以前のホスト試作の強制的な履歴消去は使いません。
シークでは全音源と両方の時刻、FIR・FIFOをリセットします。

入力の時刻と物理出力の時刻を分け、音源が終わった後も残るFIFOとFIRを流します。
将来の音符・コントローラーや生存中のATRがある間は入力を終えません。FIRの終了は有限の支持長で判定し、
小さい音を音量しきい値で打ち切りません。厳密なゼロ入力だけはFIRの末尾を延長しません。その後は既存のローパスの終了条件を保ちます。

安全上限は元の入力上限に72フレームを加え、既存のフェードも同じだけ後ろへ移します。
上限に達した異常に長い持続音は、このフェードで終えます。この場合は自然終了時のFIR全支持長より
安全上限を優先します。`totalSamples()`は延長を含む物理出力の上限、`scoreEndSamples()`は元の曲時刻です。
`finished()`は物理出力が終わった後に真になります。

## WAVで比較する

```sh
cmake -S third_party/yamaha-smaf-player -B build/native-render -DCMAKE_BUILD_TYPE=Release
cmake --build build/native-render --parallel 2
build/native-render/smaf-render original.mmf normal.wav 30
build/native-render/smaf-render original.mmf aligned.wav 30 --experimental-sine-factor=1
build/native-render/smaf-render original.mmf filtered.wav 30 --experimental-sine-factor=8 --experimental-sine-math=hermite
```

秒数は物理出力長の上限です。曲末を比較するときは、余韻と遅延を含めて収まる値を指定します。
ホストCLIでフラグを省略すると従来経路を使います。アプリには倍率の設定画面を追加せず、
r83のネイティブ初期化で8倍・Hermiteを指定します。

## 検証

- 通常の2,121件のWAVは、従来の検証済み出力とバイト単位で一致。
- 本体バスの5,400出力を既存の検証済みストリーム処理と比較し、リセットとコピー後の履歴分離も確認。
- 実際のFM・録音Audio・ATR・WT・混在16条件で、元の出力が72フレーム遅れるだけであることを確認。
- 実際のイベント処理・各音源プール・共有出力処理を、独立した密なFIR畳み込みと12,000フレームで照合。
  2演算器・並列4演算器、通常の音量・リミッターが働く多重発音、Hold、再発音、パン・音量・音程変更、個別停止を含みます。
- 20条件で1・17・512・1024フレームのブロックを比較。実際の曲のシークと安全上限のフェードも確認。
- 最後の1フレームだけの音と1e-12の小さい音を10条件で照合し、遅延中の末尾を保持。
- ATRの実際の置換・将来イベント・ミュート・16/32枠・FM/WTの持続音・シークを28条件で確認。
- CLIは引数・入力保護を11テストで確認。実際の自作MMFからWAVまで3テストで確認し、
  通常出力の正確なシフト、倍率の反映、補間方式との差（PCM16で最大1段階）を確認。

比較素材は自作の音色と波形です。旧端末や他アプリの音色再現を測ったものではありません。
端末での負荷と比較録音を踏まえた品質設定の決定は、引き続き今後の作業です。

## 無入力中のFIR演算を省く

非ゼロ入力が最後に入ってから、倍率ごとの有限の末尾をすべて処理した時点で、
FMの履歴だけをクリアして休止します。PCM等のFIFOは動き続けます。新しい非ゼロ入力で即座に再開し、
1e-280の入力も切り捨てません。プレイヤーの曲末判定は、このバスの残りフレーム数を直接使います。
独立した期限の重複管理はなくしました。

25,000フレームの休止・境界での再開・小さい入力を、常時動かしたFIRと比較して一致しました。
既存の2,121件の通常WAVに加え、1/8/32/40音の自作MMFの24条件も、休止処理の前後で
WAV全体がバイト単位で一致しています。音質と処理量の評価を分けるための最適化です。

`tools/fm-sine-output-cost.cpp`は、合成やファイル入出力を除いたバス単体を測ります。
各倍率を3回、44,100フレームずつ、無入力・1,024フレームごとの短い入力・連続入力で比較します。
共有ホストの8倍処理の中央値は次のとおりでした。

| 入力 | 休止なし | 休止あり |
| --- | --- | --- |
| 無入力 | 約9.05ms | 約0.74ms |
| 疎な入力 | 約8.89ms | 約2.49ms |
| 連続入力 | 約9.06ms | 約9.36ms |

45条件すべてでフレーム処理中の通常のC++ `new`は0回でした。共有ホストでの短い測定なので、
小さな差や端末上の速度・電力を保証するものではありません。

```sh
mkdir -p build/fm-sine-idle
c++ -std=c++20 -O2 -Ithird_party/yamaha-smaf-player/src tools/fm-sine-output-cost.cpp -o build/fm-sine-idle/cost
build/fm-sine-idle/cost > build/fm-sine-idle/cost.json
```
