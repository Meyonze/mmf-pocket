# 4演算器の並列2本の試作

[演奏中のFM診断](fm-eligibility-audit.md)で、既存の自作素材30個に、フィードバックのない
正弦波4演算器・接続5を確認しました。2本の独立した2演算器の位相変調を加算する接続です。
この範囲を`tools/fm-parallel-pair-probe.h`のホスト試作へ追加しました。
アプリ・公開版1.6.6・変換キャッシュr82は変更しません。

```text
演算器1 → 演算器2 ─┐
                   ├─ 既存モデルの0.5倍の加算 → 既存の音量・ベロシティ
演算器3 → 演算器4 ─┘
```

0.5倍は既存ソフトウェアの接続処理をそのまま保つ値です。除去した側帯波の電力を補う
正規化や、内蔵ROM音色への新しい音量校正ではありません。

## 状態更新

元の`FmVoice::tick()`をネイティブフレームにつき1回呼び、4個の演算器の更新前後の
位相・EG・AM/VIB設定から、その間のサンプルを計算します。EG・LFO・Hold・解放状態・
最近の音量による発音枠の評価は、元の速度を保ちます。最終サンプルは公開APIの出力と一致し、
別に再構成した終点とも照合します。フレーム処理中の確保はありません。

対象は4演算器・接続5・全演算器が正弦波・実効フィードバック0の場合だけです。
音色ヘッダーのフィードバックも確認します。直列4演算器、非正弦波、フィードバックは
対象外です。既存の2演算器用の適用判定を広げず、別のヘルパーとして実装しました。
本体向けAPIではなく、内部状態の観測を使うホスト専用の試作です。

## 独立した基準での確認

Release O2とASan/UBSanで確認しています。

- 8kHz／44.1kHz、互換・modern互換・VM35、AM/VIB、4種類のEG、5倍率の480条件。
  4,571,136サブサンプルで、公開APIの終点と全演算器の位相・EG・Hold、LFO、発音枠の音量評価が一致。
- 音程変更・ナイキスト超過・音量ゼロと復帰・Hold・解放・再発音を含む。
  MA7で使う非ゼロのアタック低位ビットも、ソフトウェアの既存処理と照合。
- 定常状態の86,016サンプルを、独立した2本の連続PM式と、公開APIを高いレートで進めた波形に照合。
- 選んだ時刻では、各側帯波のJacobi–Anger展開を加算した基準とも照合。終点を合わせるだけの検証にはしない。
- 因果FIRを含む20条件も、各側帯波と複素周波数応答を掛けた基準に照合。最大RMS誤差は約8.99e-8。
  VM35・変調器TL0の例では、理想帯域との差が8倍の約0.1149から32倍の約0.000477へ減少。
  音量の正規化はしない。有限FIRの境界漏れも含むため、32倍で完全一致したという意味ではない。
- 他の接続・波形・実効フィードバック・不正な倍率は、状態と出力を進める前に拒否。
- 混在試作では、フィードバック・実際の直列4演算器のネイティブ経路から、並列接続へ再発音するケースを確認。
  14,400出力の密な畳み込み、3,600出力の実FM・PCM・独立入力の比較を再実行。

## 診断上の扱い

`fm-eligibility-audit`では、従来の`eligible_voice_frames`とその倍率分類を直列2正弦波の範囲に保ちます。
並列接続は`parallel_pair_candidate_voice_frames`と`parallel_pair_model_factor_voice_frames`で別に数えます。
従来の理由別集計では`four_operator`にも含まれるので、理由別件数に並列候補を加算しません。

並列接続の定常モデルでは、2本それぞれにBessel係数の残りの上限を求め、必要倍率の大きい方を採ります。
各枝の係数の残りを1e-5以下にすれば、既存の0.5倍の加算でも全体の残りは1e-5以下です。
片側が32倍を超える場合は全体も`beyond32`です。停止済みの変調器・終了したキャリアは、
確定した無音として扱います。音量閾値は使いません。

この目安は定常モデルの係数についてのものです。動的なEG・AM/VIB・ゲート・有限FIRの誤差や、
メーカー実機の音質を保証しません。現在のコントローラーでの変動幅を観測し、LFO付きの時間も別に数えます。

318素材を再観測し、通常出力との全サンプル一致と、従来の診断項目の一致を確認しました。
既存30素材の並列接続は、このモデルでは倍率1の範囲でした。CLIには高音域の並列接続の
正例も追加し、倍率1以外の分類を確認しています。

## 次の判断

複数音源の負荷ツールは、接続0と5を分けて測るようにしました。高倍率・多数の声での負荷を見積もり、
音程・発音数・固定倍率・既存の出力経路との接続条件を決める必要があります。
4演算器全般を適用対象へ含める変更ではなく、実曲や端末での評価も未実施です。


最新のホスト測定では、2,048フレーム・8声の通常処理の中央値は次のとおりでした。
初期化とファイル入出力は含まず、診断用の終点再構成を含みます。3回の測定で変動があります。

| 接続 | 8倍 | 32倍 |
| --- | --- | --- |
| 直列2演算器 | 約16.0ms | 約46.6ms |
| 並列4演算器 | 約26.7ms | 約73.7ms |

接続0／5を含む108回の処理測定で、フレーム処理中の通常のC++ `new`は0回でした。
2,048フレームは44.1kHzで約46.4msです。これらはホスト試作の値で、端末性能の測定ではありません。

追加サンプルだけの[補間による軽量化](fm-subframe-sine.md)も検証しています。
従来方式を既定に保ち、状態と終点、追加サンプルの誤差、処理時間を別々に比較します。
