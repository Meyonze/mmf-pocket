# 音質改善の現在地と次の作業

SMAF（MMF）には、音符と音色指定から音を作る部分と、録音済みの波形を鳴らす部分が
あります。同じ拡張子でも、FM の音色再現、サンプル音の復号、音符の処理を分けて確認する
必要があります。別アプリが「高音質」としていることだけでは、どの部分が優れているかは
判断できません。Galamelo や旧端末との録音比較は、まだ実施していません。

## 修正したこと

| 対象 | 修正の意味 |
| --- | --- |
| HPS/VMA の音色選択 | バンク番号の上位ビットを保持し、別の楽器音色を選んでしまう問題を修正 |
| Hold と同時発音数 | 既に消えた音が保護され、必要な持続音を切ってしまうケースを修正 |
| ADPCM の復号 | 整数計算の端数処理を修正。独立した FFmpeg の合成信号とサンプル単位で確認 |
| 高い比率でのサンプル変換 | フィルターを改善し、確認した合成信号で折り返し雑音を低減 |
| FM の位相 | 高すぎて出力を抑えている間も時間を進め、音程が戻ったときの位相を維持 |
| 再生操作 | 停止後の意図しない再開と、再生準備・シーク中の音量変更の取りこぼしを修正 |
| 曲末の長さ | 永久に無音の FM・サンプル楽器音源に付く、不要な約10秒の無音を除去 |
| FM の処理量 | 音の揺れを使わない音では、そのための LFO を停止。音声は変更しない |
| FM 波形の処理量 | 矩形波・三角波・のこぎり波などで、使われない正弦計算を省く |
| 長い変換フィルターの処理量 | 64・128タップの係数計算をまとめ、CPU が並列に計算しやすくする |
| 繰り返す FM 波形の処理量 | 波形の繰り返しに使う剰余計算を、同じ結果を返す比較・減算へ置き換える |
| 波形が欠けた個別ドラム音色 | 既にドラムとして解釈した音色が、波形不足時だけピアノ系の代替になる問題を修正 |
| 録音済み音声の重なり | 同時刻の発音順を保持し、後続音によって新しい音のほうが先に消える問題を修正 |
| 不完全な MA-7 音色定義 | 必要な演算器データが足りない定義が、正しい音色を上書きする問題を修正 |
| 変調のない矩形波・のこぎり波 | 最終出力だけを帯域制限し、高調波の折り返しを低減。変調器・フィードバック・従来プロファイルは保持 |
| 末尾の未対応命令の時刻 | 完全に読めた指示の時刻を保ち、曲末や余韻の上限が早まるケースを修正 |
| 録音を置き換えた後の余韻 | 既に再生していない長いATR波形の予定長で、他の持続音が余分に延びる問題を修正 |
| 異なる形式が混ざる録音音声 | Mobileの録音が別トラックの波形にすり替わったり、無音になったりする問題を修正 |
| 無音ループを持つPCM音色 | 高品質補間を維持し、元の音の履歴が完全に無音になってから終了 |

ここまでの r53 は、ネイティブ10スイートのメモリ検査と Android の lint・Debug・Release
ビルドを通過しました。Java/Python の回帰検証も確認しています。曲末の処理は、静かな音や
遅い立ち上がりを音量のしきい値で切るものではありません。

未使用 LFO の軽量化では、約614万サンプルの比較と11種類の MMF の変換結果が以前と完全一致する
ことを確認しています。ホスト PC では改善傾向がありますが、端末での処理時間や消費電力は
まだ測定していません。音声を変えないため、変換キャッシュの版は r53 のままです。

波形計算の軽量化も、GCC と NDK Clang でそれぞれ約1,044万サンプルが以前と一致しました。
現在の比較素材は14種類で、実際の MMF から作った WAV もすべて変更前と完全一致します。
ホストの32音同時合成テストでは、一部の波形で約1.6〜1.9倍の改善傾向がありました。
これは端末上の音楽再生全体の速度を測った値ではありません。

続く r54 は、高い変換比率で使う64・128タップのフィルターを軽量化しています。
フィルターの式や音程・発音時刻は同じですが、コンパイラーの計算のまとめ方によって
微小な丸め差が出るため、変換キャッシュの版を更新します。追加の直接フィルター検証で
観測した最大差は、PCM16 の1段階の約0.012倍でした。あらゆる入力や端末での最大値を
保証する数字ではありません。PCM16 への丸めの境界では、出力が1段階変わる場合も
確認しています。通常のホストビルドでは、22種類の MMF の WAV が変更前と
完全一致しました。Android 実機での速度・消費電力・聴感の測定は未実施です。

r54 も、ネイティブ10スイートの ASan/UBSan、Python の35チェック、Android の
lint・Debug・Release ビルドを通過しました。再生用 Java コードは変えていません。

追加の FM 軽量化では、波形番号19・22・26・27・29の通常の剰余計算を省きました。
約1,044万サンプルを4つのコンパイラー構成で比較し、それぞれ以前と完全一致しました。
通常とは違う丸め方向でのゼロの符号も検証しています。キャッシュ版は r54 のままです。
ホストの対象波形では約1.1〜1.5倍の改善傾向がありますが、条件によるばらつきがあり、
実機での効果は未測定です。新しい波形の FM 素材を追加し、比較用 FM 素材は19種類になりました。
この追加変更も、ネイティブ10スイートのメモリ検査と Android の lint・Debug・Release
ビルドを通過しました。19種類の FM 素材の8チェックを、ネイティブと独立パーサーで
実行しています。音声トラック5種・サンプル楽器3種を合わせた27種類の比較 WAV は、
変更前の r54 と完全一致しました。

これは確認できたソフトウェアの不具合と信号処理の改善です。当時の端末 ROM の音色や
Yamaha チップそのものの再現度を測った結果ではありません。

続く r55 では、音色定義でドラムとして選択された PCM の波形がない場合にも、その指定を
保持します。バンク0・124の個別ドラムが対象で、既知の ROM 近似音色がある場合は
そちらを優先する従来の順序を保ちます。変換キャッシュを r55 に更新します。
これは既存の音色解釈の一貫性を直す変更で、端末 ROM の再現やドラム音色の調律ではありません。

r55 も、ネイティブ10スイートの ASan/UBSan、追加の Python 12チェック、Android の
lint・Debug・Release ビルドを通過しました。lint は既存の警告4件、エラー0件です。
自作42素材の WAV を修正前と比較し、対象の4素材だけが変わり、残る38素材は完全一致しました。
今回の変更に対する実機での追加確認や、別アプリ・旧端末との比較録音は未実施です。

ROM 依存の調査には、音符ごとに指定バンク・音色・波形番号と代替理由を集計する
[詳細レポート](tone-dependency-probes.md)を追加しました。ROM 指定、RAM 波形の不足、
一致する対応音色がない場合を分けます。15種類の自作素材で経路を確認でき、
録音済み音声や意図的な無音も区別します。診断ツールが元の MMF を出力先として
上書きしてしまう問題も修正しました。

r56 では、録音済み音声を置き換える順番を修正しています。再生位置だけで古さを
比べていたため、同時刻の発音を区別できず、同じ枠を繰り返し置き換えていました。
実際に発音を受け付けた順番を記録し、既存の「古い音から置き換える」動作に揃えます。
例えば、同時刻に A・B・C・D の順で指定すると、以前は B と D が残る場合がありました。
修正後は最後に指定された C と D が残ります。
2音の専用枠、音量・音程・ゲート・波形の選択は保ち、キャッシュを r56 に更新します。

16通りの自作ケースで修正前の問題を再現し、修正後は期待する最後の2音と完全一致しました。
完成した MMF 54素材の WAV 比較では、対象の6素材だけが変わり、48素材は完全一致しました。
従来の42素材はすべて同じ出力です。各対象素材は「最後の2音だけ」を書いた対照素材とも
完全一致しています。端末の音色や内部処理順を測った結果ではなく、既存の実装方針に
対する不具合の修正です。

r56 は、ネイティブ10スイートの ASan/UBSan、診断ツールの Python 12チェックの再実行、
Android の lint・Debug・Release ビルドを通過しました。lint は既存の警告4件、エラー0件です。
今回の変更についての追加実機確認や参照録音は未実施です。

r57 では、MA-7 の FM 音色定義を受け付ける際、指定された合成方式に必要な
演算器データが揃っているかを検査します。4個必要なのに2個分しかない定義を受け付け、
残りを既定値で補ってしまうケースがありました。その定義が前の正しい音色を上書きすると、
想定外の音や長い余韻につながります。今回の修正では不完全な定義を無視し、前の音色を
保持します。使える定義がない場合は、従来の代替音を選びます。キャッシュは r57 に更新します。

12通りの不完全な定義で問題を再現し、修正後の音声と再生位置リセットを確認しました。
完成した MMF 63素材の比較では、対象の6素材だけが変わり、残る57素材は完全一致しました。
対象素材も、それぞれ「不完全な定義を含めない」対照素材と完全一致しています。
これは定義の整合性の修正で、Analog Lite フィルターや端末固有音色の対応を追加するものではありません。

r57 も、ネイティブ10スイートの ASan/UBSan、診断ツールの Python 12チェック、
Android の lint・Debug・Release ビルドを通過しました。lint は既存の警告4件、エラー0件です。
今回の変更についての追加実機確認や参照録音は未実施です。

r58 では、既存の高音域抑制や、未対応のユーザー波形指定によって完全に無音となる
FM 音源についても、曲末に不要な約10秒の無音を残さず終了します。曲中の音程変更で
再び鳴る音は保ち、発音枠・位相・エンベロープの進行は変えません。ユーザー波形の
再生対応や高音域の音作りを追加する変更ではありません。キャッシュを r58 に更新します。

完成した MMF 82素材を比較し、対象13素材だけで末尾の無音が短くなることを確認しました。
残した音声サンプルは完全一致し、削った部分の PCM16 はすべてゼロです。対象素材は
それぞれ独立した対照素材とも完全一致しました。従来63素材を含む69素材は WAV 全体が
完全一致しています。後続の音程変更・コントローラー初期化で鳴り始める素材も保持します。

r58 は、全4コアオブジェクトを作り直したネイティブ10スイートの ASan/UBSan、
診断ツールの Python 12チェック、Android の lint・Debug・Release ビルドを通過しました。
lint は既存の警告4件、エラー0件です。今回の変更についての追加実機確認や参照録音は未実施です。

r59 では、Mobile 形式の未適用 CC1 が、同じチャンネルを共有する MA-7 トラックの
設定によって誤ってビブラートを変えてしまう問題を修正します。Mobile CC1 の時刻と
診断結果を保ちながら、音への適用を止めます。音色自体のビブラートと、対応済みの
MA-7 CC1 は従来どおりです。変換キャッシュを r59 に更新します。

通常・圧縮の Mobile 形式、FM・サンプル楽器、トラック順、チャンネル、指示の時刻を
組み合わせて検証しています。末尾の指示直後でデータが終わる場合も、その時刻までの
長さを保ちます。完成した MMF 108素材の比較では対象8素材だけが変わり、いずれも
未適用指示を同時刻の無処理イベントに置き換えた対照素材と完全一致しました。
従来82素材を含む100素材は WAV 全体が完全一致しています。

r59 も、ネイティブ10スイートの ASan/UBSan、診断ツールの Python 12チェック、
Android の lint・Debug・Release ビルドを通過しました。lint は既存の警告4件、エラー0件です。
今回の変更についての追加実機確認や参照録音は未実施です。

追加監査では、音源の再初期化・シークについて32組を比較し、新しいプレーヤーと
同じ音声になることを確認しました。新たな状態管理の不具合は見つかっていません。

ビブラート OFF 時の WT 計算を省く試作も調べました。GCC・Clang の各構成で約624万回の
サンプル・状態比較が一致し、最初の試作では完成 MMF 120素材の WAV も完全一致しました。
ただし、長めのホスト測定でトレモロや有効なビブラートの処理が遅くなる条件が残ったため、
2通りの試作はどちらも採用していません。このWT試作では再生コードを変えず、
当時のAPK・キャッシュはr59を維持しました。
これは端末での速度測定ではなく、ソフトウェア上の追加監査と試作の記録です。

FM 波形7〜13も公開資料・実装と照合しましたが、参照先同士で曲線が異なり、
図だけでは正しい数式を確定できませんでした。再生式は変えず、判別に使う自作 FM 素材を

完全一致です。全体の比較パックは115素材になり、[波形調査](fm-waveform-investigation.md)と
曲線の比較図も保存しています。外部プレーヤーでの受け付けや音色の正確さを保証する検証ではありません。

## r60：変調のない出力波形の折り返し低減

r60では、試作をそのまま全FM音へ適用せず、**変調を受けない最終出力の矩形波・
のこぎり波だけ**に限定して折り返し低減を組み込みました。直前の変調器がこの発音では
永久に無音の場合も対象です。音量の小ささや、その瞬間の出力ゼロで判定しません。
基音の減衰を補い、定常音では補正係数を保持し、ビブラート時には共有の小さな表を使います。

独立したフーリエ級数との12通りの比較で、二乗誤差が少なくとも75%減り、基音の振幅差は
0.1%以内でした。実際のMMF123素材では対象6素材だけが変わり、117素材は完全一致です。
全素材で長さ・形式を保持しています。これは合成信号での改善で、実機の音色再現度や
聴感上の改善率ではありません。変換キャッシュをr60に更新します。

ネイティブ11スイートのASan/UBSan、診断ツール12チェックと自己検証、FM34素材の
ネイティブ・独立パーサーによる8チェック、Android全3 ABIのlint・Debug・Releaseを
通過しました。lintはエラー0件、既存警告4件です。端末での追加の速度・聴感測定は未実施です。

## r61：末尾の未対応命令の時刻を保持

r61では、末尾に完全な未対応CCや予約命令があり、EOSがない場合の曲末を修正しました。
1秒地点まで命令を読めても30msを曲末としてしまうケースを再現し、指示の時刻を保持します。
新しい音への対応や音色変更は加えません。既存123素材のWAVはすべて同じです。
再現・対照を含む141素材では対象12素材だけの長さが変わり、129素材は完全一致しました。
詳細は[スコアの時刻復元](score-clock-recovery.md)にまとめています。キャッシュはr61です。

## r62：置き換わった録音による余韻の延長を修正

r62では、録音音声が同時発音数の制限で置き換わった後も、その長さが他の音の
余韻の上限に残る問題を修正しました。長い録音や音量ゼロの録音を途中で切る変更ではありません。
158素材の比較で対象7素材だけを修正し、既存141素材を含む151素材は完全一致しました。
詳細と比較条件は[ATRの終了時刻](atr-runtime-end.md)にまとめています。キャッシュはr62です。

## r63：録音音声の参照先を発音ごとに保持

MobileとMA-7が同じチャンネルを共有する場合、Mobileの録音音声が後から読んだ
別トラックの波形を使う問題を修正しました。その波形がないと無音になる場合もあります。
通常・圧縮形式とも、発音に元のトラック番号を持たせ、診断レポートも同じ参照先に揃えます。
既存の音量・定位の扱いは保ちます。190素材の比較で対象12素材だけが変わり、
既存158素材を含む178素材は完全一致しました。
詳細は[録音音声の参照先](recorded-source-binding.md)にまとめています。キャッシュはr63です。

## r64：無音ループを持つPCM音色にも高品質補間を適用

MA-7の一部の符号付き8ビットPCM音色では、無音ループの終了処理のために
高品質補間を外していました。補間を維持し、過去の波形がフィルターに残らなくなった
位置で終了するよう修正しました。対象の合成信号2条件では折り返し電力を約51〜54dB低減し、
低い周波数の別の信号の振幅差は約0.04%以内でした。実曲全体の改善率ではありません。
既存190素材は完全一致、新素材32個のうち対象15個だけが変化しました。
詳細は[無音ループの補間](silent-loop-reconstruction.md)を参照してください。
この変更の変換キャッシュはr64です。

## r65：高音域の三角波の折り返しを低減

変調・フィードバックがない最終出力の三角波に限り、第3倍音以上が出力範囲を超える
高音域を補正します。低・中音域の出力は維持します。単独の約8,635Hzの合成信号では、
整数倍ビン以外の成分が1.44660%から0.002792%へ減りました。
既存222素材は完全一致、新しい37素材は対象18素材だけが変化し、再生時間も維持しました。
詳細と負荷測定の限界は[三角波キャリアの補間](triangle-carrier-reconstruction.md)に記録しています。
この変更の変換キャッシュはr65です。

## r66：音程を戻した後のPCM振幅を保持

等速付近で線形補間へ戻す処理を見直し、小数の読み取り位置でも高精度の補間を保ちます。
合成MMFの音程を戻す比較で、振幅比が約0.711・0.325から約0.99975へ改善しました。
整数位置の等速再生と従来プロファイルは維持します。既存259素材は完全一致し、
新しい44素材は対象24素材だけが変わり、再生時間も維持しました。
詳細・負荷・ナイキスト直近に残る課題は[等速付近のPCM補間](native-rate-pcm-reconstruction.md)に記録しています。
この変更の変換キャッシュはr66です。

## r67：等速直上の折り返しを低減

進行比1〜1.1に限って64タップを加え、補正の両端は従来処理へ滑らかにつなぎます。
ナイキスト直近の合成信号4条件では、r66から折り返し電力を約0.65〜13dB低減しました。
既存303素材は対象10素材だけが変わり、293素材が完全一致しました。追加54素材も対象41素材
だけが変化し、再生時間とr66の振幅回復を維持しました。
追加の共有領域は約226KiBです。詳細・計算量・残る限界は[等速直上の折り返し低減](near-native-antialias.md)に記録しています。

## r68：無音指定の音符によるパートの欠落を防止

MA-7のVelocity 1とバンク121/6は常に無音ですが、以前は発音枠を使い、
32音が鳴っている状態では別の音を切っていました。この2種類は枠を使わずに処理します。
途中で音量を上げる音符は保持し、音符・ゲート・曲末の時刻も維持します。
詳細は[無音音符と同時発音数](silent-note-polyphony.md)に記録しています。

代替音色の[音量・余韻を測るツール](fallback-balance-profile.md)も追加しました。
自作280素材で、立ち上がり・持続部・余韻を分けて確認できます。MA-7の同じ音程・強弱では、
代表GM16系統の持続部に最大約7.94dBの差がありました。端末との比較音源は未取得で、
この差をそのまま不具合や補正量とは扱っていません。今回の追加は測定用で、アプリの音は変更していません。

## r69：ビブラート中の高周波抑制と曲末判定

Mobile/MA-7のFMでは、ビブラートを含む実際の位相増分でナイキスト上限を判定します。
従来は中心周波数だけを見ていたため、上限をまたぐ音が漏れたり、範囲内へ戻っても
無音のままになる場合がありました。曲末も、ビブラートで再び聞こえる音の余韻を保ちます。
既存357素材はすべて一致し、新しい70素材は対象34素材だけが変わりました。
詳細は[ビブラートと高周波抑制](vibrato-nyquist.md)に記録しています。

## r70：高い整流正弦波の折り返しを低減

半波・全波整流の正弦波も、変調のない最終出力に限って高音域を補正します。
出力レートの1/4を超える範囲で、連続波形のDCと範囲内の基音を残します。
既存707素材はすべて一致し、追加90素材は対象52素材だけが変わりました。
数式・検証・負荷の限界は[整流正弦波の高音域処理](rectified-carrier-reconstruction.md)に記録しています。

## r71：高いクリップ正弦波の折り返しを低減

クリップされた正弦波の3形状も、変調のない最終出力に限って高音域を補正します。
独立した数値積分で基音とDCを確認し、既存の音色モデルの係数を保ちます。
既存797素材はすべて一致し、追加186素材は対象78素材だけが変わりました。
詳細は[クリップ正弦波の高音域処理](clipped-sine-carrier-reconstruction.md)に記録しています。

## r72：周期の一部を止める正弦波の折り返しを低減

6形状の高い無変調最終出力も補正します。波形ごとのDC・基音・位相を積分で確認し、
余弦の基音を持つ形状も保持しています。既存983素材はすべて一致し、新しい270素材は
対象156素材だけが変わりました。詳細は[周期の一部を止める正弦波](gated-sine-carrier-reconstruction.md)に記録しています。

## r73：残る固定波形の高音域も補正

多項式・矩形・三角・のこぎり波の派生14形状を、同じ適用条件で補正します。
各形状の平均値と基音を数式・独立した数値積分で照合し、低・中音域と変調中の音を保持します。
既存1,253素材はすべて一致し、新しい868素材では対象276素材だけが変わりました。
詳細は[残る固定波形の高音域処理](remaining-carrier-reconstruction.md)に記録しています。

## r74：鳴らない発音枠を先に再利用

発音枠が満杯の場面で、鳴り始めないエンベロープの音を残したまま、旋律や余韻を
消していました。この音符では再び鳴らない枠を先に再利用します。音量・Expression・
ピッチ変更で復帰する音と、MA7の最小非ゼロアタックは保護します。
自作72条件では無音音符を除いた参照と全float出力が一致し、既存2,121素材のWAVも
すべて一致しました。詳細は[鳴らない発音枠の再利用](silent-voice-allocation.md)に記録しています。

## r75：未対応ユーザー波形の無音枠も再利用

現在ゼロを出力する未対応のユーザー波形でも、無音枠を残したまま旋律や余韻を
押し出すことを確認しました。全出力キャリアがこの波形または停止エンベロープの
場合に限り、r74と同じ優先再利用を適用します。ユーザー波形を再生できるようにする
変更ではありません。後の音量・ピッチ変更で鳴る音は引き続き保護します。

## r76：全体が無音の鍵盤PCMの枠を再利用

r76ではデータ全体がゼロの鍵盤PCMも、満杯時の優先再利用に含めます。
判定はデコード後の全サンプルで行い、1サンプルだけが非ゼロの波形も保護します。

## r77：PCMの実際の再生範囲で無音を判定

再生終了位置より後ろにだけ非ゼロのデータがある場合も、無音枠が旋律を押し出していました。
実際に再生する範囲を、補間処理と同じ終了位置で判定します。範囲内の非ゼロ1サンプルも
引き続き保護します。終了位置の直前・直後・波形長を超えた指定の36条件を追加しました。

## r78：無音PCMによる曲末の約10秒の余白を解消

鳴り止まない設定の鍵盤PCMでも、再生範囲が厳密に無音なら曲末で終了できるようにします。
曲中の音符・コントローラー・休符を維持し、後続イベントを消費し終えたときだけ適用します。
録音音声の寿命や、微小でも非ゼロのPCMは保護します。

## r79：立ち上がり後が無音ループになるPCMの曲末も改善

最初だけ鳴り、その後は無音を繰り返すPCMについても、曲末の不要な無音を解消します。
補間が立ち上がりを参照しなくなるまで保持し、非ゼロのループや録音音声は保護します。
既存2,121素材では2,104素材が完全一致し、17素材は末尾のゼロ値だけが短くなりました。
残した音声サンプルはすべて一致しています。

## r80：未使用のデータが後ろに残る無音ループも認識

ループ範囲は無音でも、再生されない後続データのために曲末の無音が残る場合を修正します。
音色のLP〜EPを厳密に判定し、立ち上がりと補間の履歴、微小でも鳴るループは保護します。
無音範囲のキャッシュを独立した直接走査と403,194範囲で照合しました。

## r81：形式が混在するファイルの音色・音量設定を分離

HandyPhone／Mobile／MA7のトラックが同じチャンネルを使う場合、音符を持たない
別トラックの設定だけで、既存の音色・音量カーブ・パン・余韻が変わる問題を修正します。
音符が元トラックの音色方針、リズム指定、FMドラムのキー指定を保持し、発音後の
音量・Expression・パン・MA7変調も各音声の形式に合う処理を使います。
バンク・プログラム・ピッチベンドなど、明示的な共有チャンネルの操作は維持します。
214ケースの波形・再生単位・シーク検証と、元の16ケースの再現テストで確認しました。
既存2,121素材のうち2,089素材は完全一致し、変化した32素材はすべて形式混在の素材です。

## r82：HandyPhoneのオクターブ指定が他形式の音程へ漏れる問題を修正

音符を持たないHandyPhoneトラックのオクターブ指定で、同じチャンネルを使う
Mobile／MA7の音程まで変わる場合を修正します。HandyPhoneの音程拡張だけに適用し、
Mobile／MA7が持つ音符番号を維持します。HandyPhone自身の移調・解除は保持します。
509チェックと、既存2,121素材のWAV完全一致で確認しました。

現在の作業版の変換キャッシュはr82です。r64〜r82は正式版には未反映です。

## 実機確認の状況

ユーザーから、都度実機確認しており、現状問題ない認識との報告があります。
通常利用の動作確認は実施済みとして扱います。条件を揃えた処理時間・消費電力の
数値測定と、Galamelo・旧端末との比較録音は別の未検証項目です。
追加の定例実機確認は求めず、具体的な症状や再現条件の確認が必要になった場合に絞ります。

## 復号済み波形の重複保管を削減

同じ波形を全体用とトラック別に二重保管していた処理を、元のトラックを参照する方式へ変更します。
検証用8波形では、復号PCMの配列確保量が32 MiBから16 MiBになりました。
音声の参照順序と再生結果は維持し、変換キャッシュはr82のままです。
詳細診断には実際の波形参照元と、同じ番号を持つトラック数を追加します。
レガシー音色からMwaへの割り当て規則そのものは実装依存で、引き続き確認が必要です。

## 停止アタックのFM演算器を軽量化

発音開始時から音量ゼロが確定する演算器について、破棄される波形計算を省略します。
位相・エンベロープ・音程変更の進行は保持し、通常の発音処理には毎サンプルの判定を追加しません。
MA7の低位ビットで非ゼロになるAR1は対象外です。専用1,024ケースと、
3,072音色条件・約315万サンプルの変更前後の完全一致で確認しています。
変換キャッシュはr82を維持します。変調FMの折り返し対策そのものは引き続き検証が必要です。

無変調の高い固定波形はr65〜r73で対策しました。低・中音域や動的な変調への対策は、
音色・接続の適用範囲と基音振幅を保てるか、独立した基準波形で確認します。

変調中の正弦波2演算器については、[独立した側帯波基準](fm-sideband-audit.md)で96条件を
測れるようにしました。単純な2倍・4倍合成では強い変調の折り返しが残り、理想的に
帯域制限すると音量も変わるため、音量バランスと処理負荷を含めて検討します。
音量制限の診断にも3/6/12dB以上の低下件数を追加し、軽い制限と強い抑制を区別します。
これらの診断追加によって、音量・音色処理の設定は変更しません（この診断追加時点のキャッシュはr79）。

r60の後にも[処理量の追加調査](fm-performance-followup.md)を行いました。
無音の変調器の波形計算を省く案などを比較しましたが、通常のFM音が遅くなる条件が残るため
採用していません。この調査では音声・公開状態の一致を確認し、本体とAPKはr60を維持しました。

比較ツールはフレーム位置・長さによる区間指定にも対応しています。
同じ録音の立ち上がりと持続音を別々に測り、範囲と結果をJSONで残せます。
詳細は[WAV の数値比較](audio-comparison.md)を参照してください。

1. **同じ自作 FM 素材を比較録音する。** 単音、音の立ち上がり・余韻、フィードバック、
   ビブラートを個別に比べます。内蔵 ROM の違いが混ざらないよう、音色を MMF 自体に
   入れた34種類の[比較用素材](fm-probes.md)を用意しています。同じ時刻の音符開始と
   音程変更の順序を入れ替えた素材も含みます。
2. **必要な場合に Android の負荷を数値測定する。** 通常利用の実機確認は前述のとおり
   実施済みです。負荷の問題が出た場合や性能を定量評価する場合に、処理時間・消費電力を
   調べます。[実機向け合成ベンチマーク](device-audio-benchmark.md)は、
   32音・22条件を同じ手順で測定できます。ホストでの動作確認と Android 3 ABI 向け
   ビルドまで完了しています。このツールによる端末での数値測定は未実施です。
3. **資料や録音で未確定の動作を決める。** 例えば、音程変更に合わせてエンベロープ速度も
   変わるのか、発音開始時の値を保持するのかは未確定です。推測で音色を調整する前に
   確認します。FM の高調波や側帯波の折り返しも、今後の測定対象です。

FM高調波については、単独キャリア4波形・3音域の[スペクトル測定](fm-spectrum-audit.md)を
追加しました。高い矩形・のこぎり波ほど、基音の整数倍以外の成分が増えることを数値で
確認しています。対策の比較基準であり、聴感の評価や旧端末との再現度の測定ではありません。
この測定だけでは再生式を変えず、r59を維持していました。現在の限定対策は前述のr60節にまとめています。

矩形・のこぎり波の[折り返し低減試作](fm-antialias-prototype.md)も行いました。
位相変調108条件を比較し、補正の効果と高音域の振幅変化を確認しています。
ただし振幅を補う案では、ホストの対象発振器の処理時間が約1.7〜2.0倍となったため、
当初の広範囲な案は採用していません。その後、補正計算の軽量化と接続の検査を加えたr60を組み込みました。

録音の条件と比較方法は[比較録音の手順](reference-capture.md)、波形側の素材は
[比較用音声の生成](audio-probes.md)にまとめています。詳細な実装・検証記録は
[audio-fidelity.md](audio-fidelity.md)と[DSP review evidence](dsp-review.md)を参照してください。

[演奏中のFM診断](fm-eligibility-audit.md)では、318の自作素材で通常出力とのサンプル一致を
確認し、実際の生存時間・同時発音数と定常側帯波の倍率目安を測っています。
低音域の単音だけで適用倍率を決めず、高い変調・多重発音と対象外の接続も調査します。

正弦波4演算器のうち[並列2本の接続](fm-parallel-pair-prototype.md)にもホスト試作を拡張しました。
約457万サブサンプルで元の状態更新を保持し、独立したPM式・側帯波と照合しています。
直列4演算器・フィードバックへの一律適用や、本体の再生方式の変更は行っていません。

[追加サンプルの正弦波計算](fm-subframe-sine.md)には、元の状態更新と終点を保つ軽量な
補間方式も用意しました。既定の計算や本体は変えず、約914万サブサンプルと40条件の
側帯波・FIR、混在音源で誤差と負荷を比較しています。
