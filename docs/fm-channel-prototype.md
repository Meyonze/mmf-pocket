# チャンネルごとのFM履歴と無音休止の試作

[整数遅延の試作](fm-aligned-prototype.md)に、チャンネル別の所有権を追加しました。
ホスト専用の`tools/fm-channel-bus-prototype.h`です。アプリの再生処理、公開版1.6.6、
変換キャッシュr82は変更しません。

## 所有権と処理

開始時に使うスコアチャンネルと固定倍率を設定し、チャンネルごとに
FMの因果FIR・追加遅延・ネイティブPCMの72フレーム遅延を持ちます。
同一チャンネルの複数の声は、ステレオで加算してから一つのバスへ渡します。
発音枠ごとにフィルターを持つ方式ではありません。フレーム処理中の動的確保はありません。

スコアチャンネルのキーは本体の範囲に合わせた0〜127です。下位4ビットなどに丸めず、
0・16・127を別々に扱います。設定外の番号、重複入力、不正なサンプル数、非有限値は、
バッチ全体の状態を進める前に拒否します。ATRは本体でも独立した音源であり、
このスコアチャンネル用バンクには混ぜません。ATRへの経路接続自体はまだ実装していません。

- `frame()`で省略したチャンネルにはゼロを入力し、蓄積済みの余韻を流します。
- `purge(channel)`は指定した処理境界で、そのチャンネルのFM・PCMの履歴だけを消します。
  発音元の声を止める処理は呼び出し側で行います。同じ境界以降の新しい入力は受け付けます。
- `reset()`は全チャンネルの履歴を消し、シークや全体停止のために使います。

非ゼロ入力を最後に受け取った後、FIRの有限長から決めた上限までゼロ入力を処理し、
残りがなくなったら休止します。音量の閾値は使いません。1e-100の小さな入力も保持します。
休止後の再入力は、新規バスと同じ位相・遅延で再開します。
これはフィルターの休止であり、発音中のFMのEG・LFO・位相更新を止める指定ではありません。

## スコア命令の時刻は別の課題

`purge()`はスコアのAllSoundOff実装ではありません。本体の既存AllSoundOffは音源を止め、
共有フィルターやリミッターの履歴を保っています。今回の試作では、明示的な履歴消去を
他チャンネルに影響させずに行えることを検証します。

音源入力の時刻nで履歴を即消去すると、72フレーム遅延で再生中の過去の音まで切ります。
一方、n+72まで待って無条件に消すと、その間に再発音した音まで失います。
命令の反映時刻と、停止の前後で入力をどう分けるかを決めてから本体へ接続する必要があります。
[遅延中の停止と再発音の試作](fm-timed-stop-prototype.md)では、停止時刻以降の入力で
履歴を再構成する候補を独立した畳み込みと照合しました。高密度の停止で負荷が増えるため、
そのまま本体へ適用する段階ではありません。

## 検証結果

`tools/fm-channel-prototype-test.cpp`をRelease O2とASan/UBSanで確認しています。

- 2／4／8／16／32倍、3チャンネル、4種類の処理区間で12,000出力を密な畳み込みと照合。
  個別消去・連続消去・全体リセット・再入力・EOFを含みます。
- 他チャンネルを消した後、残るチャンネルは単独で処理した出力と完全一致。
- 実FMのHold中の2声とPCMを消去し、再発音しても別チャンネルのFM出力を保持。
- 入力省略時も余韻が残り、上限後には全チャンネルが休止。長い休止からの再開も一致。
- PCMだけの入力と極小振幅を72フレーム後に出力。不正バッチの拒否で既存履歴が進まない。

## 負荷と次の判断

共有ホストで、FM合成を含まないバス部分だけを4,096フレームずつ測りました。
16チャンネルを設定した32倍の場合、中央値は全休止で約0.22ms、1チャンネル入力で約3.22ms、
16チャンネル入力で約59.7msでした。入力検証も含む短時間の測定で、ホスト負荷による変動があります。
端末の速度・消費電力の測定値ではありません。

休止によって無音時の負荷は減らせますが、多数のチャンネルを高倍率で処理すると負荷が増えます。
設定は実際に必要なチャンネルに絞り、音色・音程・変調量と停止命令の仕様を含めて、
共有バス方式との比較を続けます。倍率切り替え、WAVの先頭・末尾と時刻表示、
4演算器・フィードバック・非正弦波も引き続き別の検証対象です。
