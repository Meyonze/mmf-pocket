# 読み取れた未対応命令の時刻を保つ（r61）

MobileとMA-7で、未対応のコントローラーや予約命令が最後に置かれ、
EOSがない場合、指示までの時間が曲末へ反映されない経路がありました。
例えば30msのゲートの後、1秒地点に完全な未対応CCがあると、
従来のスコア終端は30msになっていました。r61では1秒を保持します。

完全に読み取れた命令だけを、同時刻の音を変えないイベントとして残します。
対応するコントローラーや圧力表現を追加する変更ではありません。

| 対象 | 保持する命令 |
| --- | --- |
| Mobile（通常・圧縮） | 未対応/適用しないCC、A0の2バイト、D0の1バイト |
| MA-7（下位・上位チャンネル） | 未対応/適用しないCC、クラス20の2バイト、クラス50の1バイト |

途中で切れた命令や、長さを確定できない命令の扱いは維持します。
Unsupported・Unapplied・Reservedの診断も変えません。
既存のノート、ゲート、音色、コントローラーの音への適用はそのままです。
従来の無音完了や共有フィルターの減衰条件も変更しません。

曲末から計算する余韻の安全上限も、修正した時刻を基準にします。
RR0の持続音の試験では、従来の10.03秒の終了位置を越えた実際の音声を保持し、
独立した同時刻のNOP指示と同じ出力になることを確認しています。
安全上限を取り除いたり、エンベロープを調律したりする変更ではありません。

## 検証

専用のネイティブ試験は2レート、MA-7上位チャンネル、圧縮Mobile、シーク、
1フレーム/大きなブロック、後続EOS、未対応指示のみの無音スコア、不完全なペイロード、
持続音の余韻を検査します。参照は同じ時刻の既知のFF00 NOPです。

比較用には18個の自作ファイルを追加しました。通常Mobile・圧縮Mobile・MA-7の
12個が問題の再現用、3個がNOP対照、3個が後続EOSを持つ対照です。
再現用は意図的にEOSを省き、命令の境界で終わらせています。
容器の長さとCRCは独立実装で検査していますが、厳密な形式適合性や他アプリでの
受け入れを保証する素材ではありません。

実ファイル141個の比較では再現用12個だけが変わり、129個はr60と完全一致しました。
既存123個はすべて一致しています。再現用の旧PCMの接頭部分も完全一致し、
追加された区間はPCM16ですべてゼロです。12個すべてが対応するNOP対照とも完全一致します。
18個の診断レポートと音色経路も、r60とバイト単位で一致しました。

これは読み取れたスコアの時刻復元の修正で、端末音色の再現度を測る検査ではありません。
変換済みWAVに古い長さが残らないよう、キャッシュ版をr61へ更新します。
