# 変調FMの折り返しを独立した基準で測定

`tools/fm-sideband-audit.cpp`は、定常的な正弦波2演算器の位相変調を、
数学上の側帯波と比較します。r73までの無変調キャリアの測定とは別に、変調中の
折り返しを検討するための開発用ツールです。アプリの音声処理は変更しません。

## 基準と条件

測る信号は `0.7 sin(2πfc t + I sin(2πfm t))` です。
Jacobi–Anger展開で、側帯波 `fc + n fm` の係数を第一種ベッセル関数 `Jn(I)` から求めます。
負の次数の符号も扱い、基準帯域内に残る周波数は `|fc + n fm| < Fs/2` です。
帯域外を捨てた後の音量を正規化して戻す処理は行いません。

- 定常正弦波・2演算器・直列接続。フィードバック、AM/VIB、変化するEGは対象外です。
- 出力44.1kHz、4,096フレーム。整数の周波数ビンを使い、窓端の不連続による漏れを避けます。
- ソフトウェアの互換プロファイルとVM35プロファイル、基音ビン1/17/67/211、演算器倍率2:3・5:7・7:9、変調器TL0/12/24/36の96条件です。
- 変調深さは現行ソフトウェアの0.42/4.0周期を独立した定数として固定します。メーカー実機で校正した値とは扱いません。
- `n=-96..96`を計算します。ベッセル係数の二乗和と、独立した16,384点の数値積分で十分な範囲と係数を検査します。

`native_error_rms`は実際の公開`FmVoice`出力と帯域制限した基準の差です。
許容した倍音ビン以外だけを数える手法と違い、折り返しが既存成分と同じ周波数に
重なる場合も、振幅の差として含めます。エンジンのfloat丸めも含むため、純粋な
折り返しだけの値とは呼びません。`full_equation_error_rms`が、帯域制限しない
独立した数式とエンジンの誤差を示します。

## 実行

```sh
cmake -S third_party/yamaha-smaf-player -B build/sideband-render -DCMAKE_BUILD_TYPE=Release
cmake --build build/sideband-render --target smaf -j2
c++ -std=c++20 -O2 -Ithird_party/yamaha-smaf-player/src tools/fm-sideband-audit.cpp build/sideband-render/libsmaf.a -o build/sideband-render/fm-sideband-audit
build/sideband-render/fm-sideband-audit --self-test
build/sideband-render/fm-sideband-audit > build/sideband-render/sidebands.json
build/sideband-render/fm-sideband-audit --oversampling > build/sideband-render/offline-experiments.json
```

`--oversampling`は高い音程・変調器TL0の6条件だけを、2/4/8/16/32倍で合成し直します。
周期的なFFTで理想ローパスを掛けてから間引き、基準と比較します。
これは定常波形のオフライン実験です。因果的なフィルター、曲の立ち上がり・音符の切り替え、
実機の遅延・負荷・電力を再現する方法ではありません。

## 初回結果

r79相当のエンジンで、96条件の帯域制限しない数式との最大RMS誤差は約1.91e-7でした。
低音の対照は帯域制限した基準とも一致します。高い音程では、強い変調により
側帯波が増え、現在のサンプルレートで折り返す成分が明確に残ります。

高い音程・TL0の例の誤差RMSは次の通りです。0.7を最大振幅とする単一ボイスの
ソフトウェア出力で、アプリの共有LP・リミッター・他のパートは含めません。

| プロファイル・倍率（キャリア:変調器） | 現行 | 2倍＋理想LP | 8倍＋理想LP | 32倍＋理想LP |
| --- | ---: | ---: | ---: | ---: |
| 互換 2:3 | 0.13619 | 1.89e-6 | 8.86e-9 | 4.61e-9 |
| 互換 7:9 | 0.43586 | 0.12839 | 9.07e-9 | 4.64e-9 |
| VM35 2:3 | 0.47613 | 0.33294 | 6.37e-8 | 3.19e-8 |
| VM35 7:9 | 0.48879 | 0.32392 | 0.15397 | 3.21e-8 |

強い変調では8倍でも十分でない条件があります。単に一定倍率で合成を増やすだけで
幅広い音色を対策できるとは判断できません。帯域内に残る音の電力も下がるため、
誤差だけを見て適用すると、音量バランスや音色の変化を見落とします。

この測定から、個別の曲の原因、メーカー音源への忠実度、聴感上の改善を確定することは
できません。現実の対策には、変化するエンベロープ・複数段の変調・フィードバック・
因果フィルターの遅延・Android負荷を含む検証が必要です。本体への採用は行っていません。

## 検査

自己検査は、ベッセル係数の独立した積分・エネルギー、FFTと直接DFT・逆変換の一致、
理想ローパスの振幅・位相・間引き位置を確認します。全96条件で、公開エンジンと
帯域制限しない数式の一致も確認します。

`python3 tools/fm-sideband-audit-cli-test.py --binary <実行ファイル>`は、JSON形式、
全条件の一意性と有限値、低音対照、高音の誤差、オフライン実験の条件数と32倍での
収束、引数の扱いを検査します。通常ビルドとASan/UBSan付きで検証します。


## 因果FIRによる追加検証

`--causal-oversampling`で、実時間向けの段階的な間引きも検証できます。
480条件の信号誤差、固定遅延、演算数、高音域の減衰を報告します。
[方式・測定結果・適用前に残る検証](fm-causal-audit.md)を参照してください。
アプリへの組み込みは行っていません。
