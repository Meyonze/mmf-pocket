# r83：通常再生で限定した変調FMの折り返しを低減

後続の適用拡張は[r84の接続7](fm-algorithm7.md)、[r85以降の自動密度](fm-adaptive-density.md)、
[r87の無音枝で簡約できる接続3/4/6](fm-reduced-graphs.md)を参照してください。
[r90では弱いVM35の直列3演算器部分](fm-weak-nested-r90.md)も16倍で処理します。

作業版アプリの通常再生・プログレッシブ変換・WAV保存で、正弦波だけの
2演算器直列（接続0）と4演算器並列ペア（接続5）に8倍の合成と因果FIRを使います。
実効フィードバックがある音色は対象外です。途中の正弦波は検証済みのHermite補間を使い、
音符・エンベロープ・LFO・発音枠の状態更新と元のサンプル終点は従来の速度を保ちます。

PCM・録音Audio・独立ATR・その他のFMは、従来の合成を72フレーム遅延させて合わせます。
全音源を揃えてから共通の出力ローパス、リミッター、必要なら携帯風処理を通します。
44.1kHzで約1.63msの遅延が加わります。曲末のFIFOとFIRの余韻を流し、シーク時は
履歴をリセットします。音色ごとの音量補正や、消えた折り返し成分を補う正規化は加えません。

変換キャッシュをr82からr83へ更新し、古い変換音声の再利用を避けます。アプリのバージョンは
まだ1.6.6のままで、正式公開は別作業です。倍率の設定画面は追加していません。
ネイティブAPIやホストCLIの既定は従来方式を保ち、比較用途では引き続き方式を明示できます。

## 選択の根拠と限界

[公開プレイヤーの側帯波測定](fm-player-sidebands.md)では、キャリア倍率5・変調器倍率7・
TL0・音程84の例で、理想帯域基準とのRMS誤差が約0.2045から8倍で約1.02e-5へ低下しました。
同じ音色の音程96では、8倍でも約0.0969が残り、16倍が必要な例も確認しています。
8倍は対象範囲の折り返し低減と負荷の折衷であり、全音色・全音域で除去できる設定ではありません。
上記は自作音色とソフトウェアの独立数式基準で、旧端末や他アプリの音色再現の評価ではありません。
対象音色は不要な成分が減ることで音量も変わり、密なミックスでは共通リミッターの動作も変わります。

共有ホストの自作3秒素材（発音ゲート1.5秒、32発音要求）では、ファイル入出力を含む変換が
通常約0.20秒、8倍約0.73秒、16倍約1.24秒でした。単発のホスト測定であり、Androidの
速度や電力を保証しません。端末の数値測定は未実施です。強い変調や対象外の接続の改善は残ります。

## アプリ経路の検証

`tools/pcm16-bridge-test.cpp`で実際の`native_bridge.cpp`を使い、通常初期化が
8倍・Hermiteの独立指定と一致し、音声変化が単なる遅延ではないことを確認します。
自作の強い変調FMをWAV/JNI双方のテストへ加え、携帯風の有無、1/31/1024フレーム、
シーク、EOF、小音量、非有限値、書き込み失敗時の中断・最終化も検証します。
書き込み失敗時は物理出力の進行を検査し、初期・途中失敗では入力クロックの即時停止も検査します。
ReleaseとASan/UBSanで通過しています。これはホストのJNIコールバックを使った検証です。

実際のアプリWAVを、6種類の音源構成と1/8/32/40発音要求の計10素材で、
ホストの明示8倍・Hermite変換と比較し、WAV全体が一致しました。FMのないPCM・Audio・ATR・
ATR+PCMでは、従来WAVに72フレームの無音を足したものと音声サンプルが完全一致します。
Android全ABIのDebug/ReleaseビルドとLintも通過しています。


r91では[MA7接続6](fm-ma7-nested-r91.md)も限定した範囲で16倍を使います。
実WAV/JNIの検査は36構成へ拡張し、MA7のFormat3・展開音色・分数倍率、固定周波数・
Detune・停止アタック・非正弦波の対象外条件を含めています。
