# 強い直列FM：安定した基準計算と64/128倍の試作

強いVM35接続6の検証を、TL18/12/0と64/128倍まで進めました。
以下はホスト専用の試作です。通常再生の範囲、変換キャッシュr91、正式版1.6.6は維持しています。

## 基準計算の修正

従来の二重Bessel展開を大きい次数へ広げると、標準ライブラリーの`cyl_bessel_j`が
非有限値になる条件がありました。`fm-bessel-reference.h`で整数次数の下向き漸化式を使い、
途中でスケールを調整し、`J0 + 2Σ J_even = 1`で正規化します。
異なる二つの打ち切り位置が収束しなければ、基準計算自体を失敗させます。

70桁で求めた6つの固定値、標準ライブラリーと重なる1,024点、係数のエネルギー・符号を
照合しています。非常に小さい引数は、補正が浮動小数点精度を下回る級数の先頭項で扱います。
元のVM35/MA7の1,500設定と108過渡条件も引き続き検査します。

展開の次数は変調指数に応じて増やします。従来の絶対尾部上限で打ち切り誤差を評価し、
省略係数の絶対値和も検査します。係数和と入れ子の正弦波の直接計算は、位相の大きい点での
丸め差を抑えるためlong doubleで照合します。基準には演算器のnative Nyquistミュートを含めます。

## 試作の構成

`fm-nested-sine-probe.h`の既定の上限32倍は維持し、明示したホスト用テンプレートだけが
64/128倍を許可します。元のtickは一回で、終点のサンプルと位相・EG・LFO・Hold・再発音は
nativeと照合します。通常再生用の公開ソースとバスの上限32倍は変更していません。

`fm-high-density-probe.h`は既存の33/37/257タップの係数・ステレオ段を使います。
64倍では8→4の段、128倍では16→8の段だけ37タップにし、最後の257タップと合わせて
群遅延を72フレームへ揃えます。密な畳み込みでインパルス、DC、左右、有限の余韻、
リセット、不正ブロックの拒否を検査します。

48の定常設定と独立した有限FIR/LPモデルの最大RMS差は約1.70e-7でした。
短音・二半音の音程変更・強制停止・RR15の通常NoteOffも48条件で比較し、
最大RMS差は約6.65e-8、ピーク差は約3.80e-7です。24条件の時計・元の終点の検査も通過しました。
GCC Release、ASan/UBSan、NDK ClangのLinuxホスト向け実行で確認しています。

## 必要倍率の根拠と負荷

`fm-nested-tail-bound.h`は、定常時の係数尾部に対するホスト用の上限を試します。
周波数をf、変調指数をβとし、時刻を`t - i y/(2π)`へ拡張すると、直列部分の絶対値は

```text
exp(φ(y)),  φ(y) = fC y + β2 sinh(fM y + β1 sinh(fI y))
```

以下です。ParsevalとCauchy–Schwarzを使い、既知の周波数格子Δfに対して、
しきい値T以上の正負の係数の絶対値和を次で抑えます。

```text
2 exp(φ(y) - T y) / sqrt(1 - exp(-2 Δf y))
```

直接音も別に加え、複数のyから小さい上限を選びます。格子が合わない入力は拒否します。
Tを`倍率 - 0.5`として、全6音色の24条件と、変調指数が異なる8条件の二重Bessel係数和で照合します。
これは定常時に高い周波数から折り返す成分の上限です。有限FIR全体の誤差、EGやコントローラーの
過渡誤差を保証するものではなく、まだ通常再生の倍率選択には使いません。

同一CPUへ固定し、倍率の順番を交互にした7回の測定では、4,096フレーム（約92.9msの音声）に
必要なCPU時間の中央値は以下でした。スカラーの試作ソース・ミックス・共有ステレオFIRだけの値です。
実装済みの演算器ごとの並べ替え、LP、リミッター、JNI、入出力は含まず、Android性能ではありません。

| 同時発音 | 16倍 | 32倍 | 64倍 | 128倍 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 6.2ms | 11.0ms | 20.0ms | 39.6ms |
| 8 | 45.0ms | 80.6ms | 139.9ms | 284.9ms |
| 32 | 169.6ms | 302.2ms | 558.0ms | 1,054.5ms |

共有ホストのばらつきがあります。通常再生への適用には、必要な音色・音程だけで高倍率を使う
計画、ソース処理の軽量化、実際のプレイヤーでの混在・曲末・負荷の検証が必要です。
音量正規化や実機チップへの一致を示す変更ではありません。

```sh
c++ -std=c++20 -O2 -Ithird_party/yamaha-smaf-player/src \
  tools/fm-high-density-cost.cpp build/native-render/libsmaf.a -o fm-high-density-cost
./fm-high-density-cost 64 8
```


## 軽量化と倍率選択の続き

[漸化式と演算器ごとの処理、格子に依存しない尾部上限](fm-recursive-nested-prototype.md)へ
進めています。64/128倍の負荷を下げ、定常時に予算を満たす倍率を選ぶホスト試作です。
通常再生へは、実プレイヤーの切り替え・曲末・混在負荷の検証後に適用します。
