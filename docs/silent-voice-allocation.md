# 鳴らないエンベロープの発音枠を先に再利用（r74）

発音枠が満杯のとき、エンベロープが鳴り始めない設定の音が枠を占めたまま、
鳴っている旋律や余韻を押し出していました。r74では、この音符では確実にゼロのままの
枠を先に再利用します。任意の音量しきい値や、音色間の音量調整は加えません。

## 選び方

HandyPhoneの同一パートの再トリガーと、空き枠の優先は保持します。
空き枠がない場合だけ、次の順で選びます。

1. 全出力エンベロープが停止・終了し、この音符では再び鳴らない枠。
2. 従来と同じ、音量の小さいリリース中の枠。
3. 従来と同じ、押鍵中の枠をラウンドロビンで選択。

FMは全8接続の実際の出力キャリアを調べます。変調器やフィードバックは、
出力キャリアのゼロのエンベロープを迂回できません。設定する演算器数と接続が
矛盾する公開API上の合成パッチは、安全側としてこの判定から除外します。
PCMは鍵盤音色のエンベロープだけを調べ、独立した寿命を持つATR・録音Audioを除外します。
共有の出力フィルター履歴は消しません。

音量ゼロ、Expressionゼロ、高すぎる音程、最初のサンプルがゼロという理由では
選びません。後のコントローラー操作・ピッチ変更で復帰する音や、極めて小さい
非ゼロの音は保持します。MA7のAR0でも、攻撃レートの下位ビットが有効なら保護します。

音符は従来どおり登録・割り当てされます。無音設定のNoteOnを一律に飛ばす変更では
ありません。既に全枠が鳴っている場面に新たな無音NoteOnが来る場合の扱いは
変えていません。r68のMA7固定無音音符の抑制とは別の処理です。

使用中の枠の再利用なので`stolenFm`・`stolenPcm`には数えますが、
`stolenHeldFm`・`stolenHeldPcm`を増やさず、押鍵中のラウンドロビン順も進めません。
新しい音別の状態やメモリ割り当ては加えません。変換キャッシュはr74です。

## 専用検証

`tools/silent-voice-allocation-test.cpp`は、自作音色・自作PCMによる72条件で、
無音の音符を除いた参照曲とfloat出力全体の完全一致を確認します。
Mobile・MA7、FM32音・PCM16/32音、MA7上位チャンネル、押鍵音と余韻の保護、
後続の発音、同一キーの再利用後に来る古いゲート、1/257/1024フレーム単位の再生と
シークを含みます。修正前は発音枠の比較で失敗し、修正後は通過しました。

別の検査では、全8接続の各キャリア、変調・フィードバック、XOF・Hold、
微小非ゼロ音量、MA7の最小非ゼロアタックを確認します。満杯のプールでも、一時的な
音量・Expressionゼロとナイキスト抑制中の音は保持され、後の操作で実際に復帰します。


## 全体検証

全音声回帰、今回の発音枠、r68の無音音符、残る固定波形、FM位相、既存FM帯域制限、
高周波ビブラート、PCM16/JNIブリッジ、入力保護、音色経路の10スイートがASan/UBSan付きで
通過しました。ローカルでは`ASAN_OPTIONS=detect_leaks=0`でリーク検査を無効にしています。
既存2,121素材のWAVはすべて完全一致し、専用の密集音符だけで修正の効果を確認しました。
Androidの3 ABIのDebug・Releaseとlintも通過しました。lintはエラー0件、既存警告4件です。
