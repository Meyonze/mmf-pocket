# 鳴らないエンベロープの発音枠を先に再利用（r74〜r75）

発音枠が満杯のとき、エンベロープが鳴り始めない設定の音が枠を占めたまま、
鳴っている旋律や余韻を押し出していました。r74では、この音符では確実にゼロのままの
枠を先に再利用します。任意の音量しきい値や、音色間の音量調整は加えません。

## 選び方

HandyPhoneの同一パートの再トリガーと、空き枠の優先は保持します。
空き枠がない場合だけ、次の順で選びます。

1. 全出力エンベロープが停止・終了し、この音符では再び鳴らない枠。
2. 従来と同じ、音量の小さいリリース中の枠。
3. 従来と同じ、押鍵中の枠をラウンドロビンで選択。

FMは全8接続の実際の出力キャリアを調べます。変調器やフィードバックは、
出力キャリアのゼロのエンベロープを迂回できません。設定する演算器数と接続が
矛盾する公開API上の合成パッチは、安全側としてこの判定から除外します。
PCMは鍵盤音色のエンベロープだけを調べ、独立した寿命を持つATR・録音Audioを除外します。
共有の出力フィルター履歴は消しません。

音量ゼロ、Expressionゼロ、高すぎる音程、最初のサンプルがゼロという理由では
選びません。後のコントローラー操作・ピッチ変更で復帰する音や、極めて小さい
非ゼロの音は保持します。MA7のAR0でも、攻撃レートの下位ビットが有効なら保護します。

音符は従来どおり登録・割り当てされます。無音設定のNoteOnを一律に飛ばす変更では
ありません。既に全枠が鳴っている場面に新たな無音NoteOnが来る場合の扱いは
変えていません。r68のMA7固定無音音符の抑制とは別の処理です。

使用中の枠の再利用なので`stolenFm`・`stolenPcm`には数えますが、
`stolenHeldFm`・`stolenHeldPcm`を増やさず、押鍵中のラウンドロビン順も進めません。
新しい音別の状態やメモリ割り当ては加えません。変換キャッシュはr74です。

## 専用検証

`tools/silent-voice-allocation-test.cpp`は、自作音色・自作PCMによる72条件で、
無音の音符を除いた参照曲とfloat出力全体の完全一致を確認します。
Mobile・MA7、FM32音・PCM16/32音、MA7上位チャンネル、押鍵音と余韻の保護、
後続の発音、同一キーの再利用後に来る古いゲート、1/257/1024フレーム単位の再生と
シークを含みます。修正前は発音枠の比較で失敗し、修正後は通過しました。

別の検査では、全8接続の各キャリア、変調・フィードバック、XOF・Hold、
微小非ゼロ音量、MA7の最小非ゼロアタックを確認します。満杯のプールでも、一時的な
音量・Expressionゼロとナイキスト抑制中の音は保持され、後の操作で実際に復帰します。


## r74の全体検証

全音声回帰、今回の発音枠、r68の無音音符、残る固定波形、FM位相、既存FM帯域制限、
高周波ビブラート、PCM16/JNIブリッジ、入力保護、音色経路の10スイートがASan/UBSan付きで
通過しました。ローカルでは`ASAN_OPTIONS=detect_leaks=0`でリーク検査を無効にしています。
既存2,121素材のWAVはすべて完全一致し、専用の密集音符だけで修正の効果を確認しました。
Androidの3 ABIのDebug・Releaseとlintも通過しました。lintはエラー0件、既存警告4件です。


## r75：未対応ユーザー波形の枠

WS15・23・31は、現在の実装ではユーザー波形が結び付かず、常にゼロを出力します。
このような音が発音枠を満たしても、現在鳴っている旋律や余韻を押し出していました。
全出力キャリアが停止エンベロープまたはこの無音波形なら、同じ優先再利用を適用します。

音量・ピッチ・ビブラート・Holdは、割り当て済み音符の波形の結び付きを変更しません。
1キャリアでも非ゼロのエンベロープと通常波形を持てば保護します。接続と演算器数が
矛盾する合成パッチも引き続き除外します。波形番号を32でマスクする既存の挙動を保ち、
従来/modernの両方を対象にします。

ユーザー波形の再生を実装する変更ではありません。将来、発音中の波形の結び付きを
更新する機能を追加する際は、この永久ゼロの判定も更新する必要があります。
高音域再構成で使う「上流エンベロープ停止」の判定には変更を加えません。
EOFの無音判定も従来と同じ条件を共有関数へ移しただけです。音符の登録・時刻・
ルーティング・発音枠の上限・ラウンドロビン順はr74の方針を保持し、キャッシュをr75にします。

専用検査には、3波形・Mobile/MA7・押鍵音/余韻・後続発音・再生ブロック・シークの
72条件を追加しました。r74の72条件と合わせて144条件です。全8接続・従来/modern・
マスクされた波形番号・1キャリアだけが鳴る混在音色も確認します。
修正前は、無音の音符を除いた参照曲との一致検査が失敗しました。


r75では発音枠・r68の固定無音音符・固定波形・FM位相・帯域制限・高周波ビブラート・
PCM16/JNIブリッジ・入力保護・音色経路の9スイートがASan/UBSan付きで通過しました。
既存2,121素材のWAVはすべて一致し、Androidの3 ABIのDebug・Releaseとlintも通過しました。
全音声回帰はr74で完了済みです。r75のローカルでは上記の専用・関連検査を実行しました。


## r76：データ全体がゼロの鍵盤PCM

デコード済みの波形が全サンプル厳密にゼロの場合も、空き枠がないときの優先再利用に
含めます。判定はデコード後に一度だけ行い、音符ごとの波形走査を加えません。
空き枠があるときの登録・ソース位置・終了処理を保持し、ATR・録音Audioは除外します。
波形の一部がゼロのループや、非ゼロの立ち上がりを持つ波形はこの判定に含めません。

Mobile/MA7・押鍵音/余韻・後続発音・ブロック変更・シークの24条件を追加しました。
1サンプルだけ値1があるPCMは再利用対象にならないことも確認します。
修正前は無音音符を除いた参照との一致検査で失敗しました。キャッシュはr76です。


r76は発音枠・固定無音音符・PCM16/JNIブリッジ・入力保護・音色経路・ATR再生寿命・
録音音声のソース分離の7スイートをASan/UBSan付きで通過しました。
既存2,121素材のWAVはすべて完全一致し、Androidの3 ABIのDebug・Releaseとlintも通過しました。
ローカルではリーク検査を無効化しています。r75のGitHub全体検査も成功済みです。


## PCMの形式・波形バージョンの追加検証

r76のGitHub全体検査は[すべて成功](https://github.com/Meyonze/mmf-pocket/actions/runs/42114571023)しました。
その後、アプリの音声処理を変更せずに、次の84条件を追加しました。

- PCM8の符号付き・符号なし、MA3の7ビット梱包、MA5の生データ、MA7の符号付き・符号なし音色RAM。
- セットアップ内の波形と再生中の波形定義、Mobile/MA7、ブロックサイズ変更、シーク。
- 圧縮データの全バイトがゼロでも、ADPCMのデコード後が非ゼロなら押鍵音を保護する対照。
- RAMをゼロから非ゼロ、非ゼロからゼロへ更新したとき、保持中の音は割り当て時のソースと無音判定を維持する対照。

形式の72条件と保持中のバージョン変更の12条件を加え、発音枠の検査は合計252条件になりました。
従来からゼロループを終了するMA7符号付きPCM8では、その既存の寿命処理も保持します。
この追加検証は新しいコーデックへの対応や音色調整ではなく、r76の形式別の確認です。
変換キャッシュはr76のままです。

追加した検査はホストの通常ビルドとASan/UBSan付きビルドで通過しました。ローカルのリーク検査は無効化しています。
