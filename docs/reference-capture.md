# 別アプリ・旧端末との比較用録音

MMF Pocket と別の SMAF 再生アプリ、または旧端末で**同じ MMF**を再生し、
音色と再生経路の違いを確認する手順です。相手アプリの内部実装や画面構成は仮定しません。
「当時の音色・発音の再現」と「リサンプリングの雑音・折り返しの低減」は別々に評価します。
この手順自体は実機での再現性を検証した結果ではありません。

## 1. 入力と条件を固定する

- 自分が所有し利用できる MMF、または合成した MMF を両方にそのまま渡します。
  ファイル名と SHA-256 を記録すると、同じ入力であることを後から確認できます。
- アプリ名・バージョン、OS、端末機種、出力モード・サンプリング周波数、
  アプリ内音量・端末音量、音源など選べる設定を記録します。不明な項目は不明とします。
- 可能なら Bluetooth を避け、EQ・音量正規化・音響効果を無効にします。
  無効にできない処理や自動音量調整は記録します。旧端末は接続方法と録音入力ゲインも残します。

## 2. 同じ区間を録る

1. WAV/PCM の直接出力があれば優先し、各出力のビット深度・周波数・チャンネル数を記録します。
   なければ有線録音やシステム録音など、利用できる方法を使います。
2. 再生開始前から、最後の余韻が消えるまで録ります。同じ条件で短い再録も行い、
   録音ごとに開始時刻や音量が変わらないか確認します。
3. 元の録音を保存し、開始位置を揃えた比較用コピーを別に作ります。
   切り出した区間・移動量・形式変換を記録します。

録音経路は、例えば「端末の有線出力 → USB オーディオ入力 → PCM16 WAV」や
「システム録音 → 非可逆圧縮ファイル」のように残します。スピーカー・マイク経由なら
距離や部屋も影響します。非可逆圧縮やシステム側の処理がある録音は、その経路を含む比較です。
MMF・録音・秘密情報はローカルで扱い、私的な素材をリポジトリや外部サービスへアップロードしません。

## 3. 数値と聴感を分けて比較する

- **タイミング:** 音符の開始、テンポ、発音の欠落、曲の長さ、余韻を確認します。
  録音開始のずれと、再生中に増える時間のずれを区別します。
- **元の振幅:** 音量を変えていないコピーでピーク・RMS・DC・左右差を確認します。
  録音入力ゲインが違う場合、その差も含まれるため再生エンジンだけの差とは扱いません。
- **聴き比べ:** 別のコピーまたは再生側の調整で聴感上の音量を揃え、同じ区間を A/B 比較します。
  調整量を記録し、音色・アタック・余韻・ビブラート・伴奏とのバランスと、雑音を個別に記録します。

[WAV の数値比較](audio-comparison.md)の `tools/compare-wav.py` は、開始位置が揃った、
同一サンプリング周波数・同一チャンネル数の非圧縮 PCM16 WAV が対象です。
自動の位置合わせ・リサンプリング・音量調整は行いません。条件が違う録音を変換して比較する場合は、
元データを残し、変換条件とその影響を明記します。サンプル差分の小ささを音色再現の点数にはしません。

開始位置を揃えた後は、同ツールの `--start-frame` と `--frames` で立ち上がりと持続音を
別々に集計できます。例えば44,100 Hzなら `--start-frame 22050 --frames 22050` で
0.5〜1.0秒を選びます。区間の一致はファイル全体の一致ではないため、全体の長さと
余韻の比較も別に残します。指定値とJSON出力を保存すると、切り出しファイルを増やさず再現できます。

## 合成素材で確認できる範囲

合成 WAV や、それを音声トラックだけの MMF に格納した素材は、音声トラックのデコードや
リサンプリングの確認に使えます。FFmpeg の MMF muxer で作った素材もこの範囲です。
FM 音源・ROM 音色・端末固有の発音を検証する素材ではありません。
結果には、使用素材・録音条件・観察できた差と、まだ比較していない音源や実機を分けて記録します。
