# r60以降のFM処理量の追加調査

追記：この調査の後、時刻復元・ATR終了時刻・録音参照先の修正で本体はr63になりました。
ここに記録した軽量化は引き続き不採用で、下記のr60は調査時点の凍結版です。

今回の2系統の軽量化は、どちらも本体へ採用していません。
再生コード、変換キャッシュ、APKは検証済みのr60を維持しています。

## 調べた案

位相が厳密に0より大きく1未満なら、そのまま使って正規化の床関数を省く案を試しました。
GCCのホスト測定では改善しましたが、ARM64のClang出力には追加の比較・分岐が入りました。
Androidで速くなる根拠は得られていないため、ホストの結果だけでは採用しません。

もう一つは、発音中ずっと出力がゼロになるエンベロープを持つ変調器について、
位相・エンベロープの進行を維持し、波形計算だけを省く案です。
無音の判定はr60の停止アタック判定を使い、静かな音やMA7の奇数アタックは除外します。
最終出力、未使用の演算器、不完全な演算器構成も対象から外します。

試作では、通常処理に判定を加える案、無音を含む音だけ処理を分ける案、
テンプレートによる特殊化、インライン化、既存のフィールド配置を保つ案を比較しました。
最終案でも通常のFM音の処理時間が増える条件が残ったため、採用を見送りました。

## 音声と状態の検証

進行を維持する試作v3は、GCC14.2とNDK Clang18のホスト実行で、4種類の丸め設定を
それぞれ比較しました。32波形・8アルゴリズム・2プロファイル・2レート・
停止/奇数/低音量アタック・AM/VIB有無の6,144組を256フレームずつ進めます。
Hold、NoteOff、音程変更とナイキスト越えも途中に入れています。

各比較の1,572,864フレームで、出力float、recent level、active/released/mutedの
全バイトが基準と一致しました。合計12,582,912フレームの比較です。
波形を省く場合も時間を止めないことを確認するための、ソフトウェアの検証です。
内部フィードバックのゼロの符号や浮動小数点例外フラグまで同一とする検証ではありません。
後続の分岐構成の試作では、負荷測定時の全ケースで出力二乗和も一致しましたが、
この集計一致を全サンプルの一致の証明としては扱いません。

## 処理負荷と判断

32個のFmVoiceを使い、単音、直列FM、混合接続、フィードバックの4条件、
サイン・矩形・のこぎり、AM/VIB有無の24条件を比べました。
別プロセスによる交互測定の後、両コアを別名前空間で一つのプログラムへリンクし、
同じCPU・同じプロセスで測る方法でも確認しています。
後者は2,048フレームのウォームアップ後、32,768フレームずつ交互順に5組測ります。
両コアは同じ回数だけ進むため、同じ区間の信号を比較します。

最終試作v7のClangホスト測定では、対象の無音変調器を持つ単音は、処理時間の中央値比が
約0.53〜0.88でした。一方、通常の直列FMでは最大約1.23、混合接続・フィードバックでも
最大約1.11の条件が残りました。値は基準r60に対する処理時間の比で、1より大きいほど遅くなります。
GCCの別案でも通常音に負荷が増える条件があり、既存の音を広く遅くしない改善とは判断できません。

これは仮想化されたホストでの探索的な測定で、Androidの速度や電池消費ではありません。
速度比の端末一般への適用、全条件の無劣化、聴感上の改善を主張するものではありません。
音声の一致だけで性能変更を採用しないための記録です。

## 保存内容

調査ZIPには、凍結したr60コアと各試作、比較プログラム、ARM64アセンブリー、
生の負荷測定JSON、トレースのSHA-256と検証条件を含めます。
巨大な生トレース、ビルド生成物、メーカー素材、個人の楽曲は含めません。
本体に変更がないため、ネイティブ全スイートやAndroid全ABIの再ビルドは繰り返していません。
作業中の本体ソースと既存APKが、凍結したr60のハッシュに一致することを確認しています。

例えば凍結した最終案のペア測定は、ZIPをルートへ展開して次の手順で再実行できます。
結果は新しいファイルへ保存してください。コンパイラーとCPU、最適化条件を揃えて比較します。

```sh
c++ -std=c++20 -O3 -DNDEBUG -Dfxchain=baseline_fxchain \
  -Ibuild/r60-floor-study -c build/r60-floor-study/ma_fm_core-baseline.cpp -o /tmp/mmf-base.o
c++ -std=c++20 -O3 -DNDEBUG -Dfxchain=candidate_fxchain \
  -Ibuild/r60-silent-modulator-v7 -c build/r60-silent-modulator-v7/ma_fm_core.cpp -o /tmp/mmf-trial.o
c++ -std=c++20 -O3 -DNDEBUG build/r60-silent-modulator-v7/paired.cpp \
  /tmp/mmf-base.o /tmp/mmf-trial.o -o /tmp/mmf-paired
/tmp/mmf-paired > /tmp/mmf-paired.json
```


## 固定波形の高音域処理後の短絡候補

r73のあと、Fs/6以下の固定波形を補正関数への分岐前に従来の生波形へ戻す案を
ホストで試しました。矩形BLEP（WS6）・のこぎりBLEP（WS24）は低音域でも補正するため
除外します。全32波形・2レート・従来/modern・AM/VIB・境界音程・Hold・ピッチ変更・
位相変調入力の約288万サンプルで、出力ビットと公開寿命状態は一致しました。

32演算器・131,072フレーム・4往復のCPU時間測定では、低音域の比率中央値は約0.97でしたが、
形状ごとの比率は約0.69〜1.37とばらつきました。高音域でも約0.84〜1.37となり、
安定した効果を確認できないため本体には採用していません。Android実機の負荷・消費電力は
未測定です。単純な処理の省略が、コンパイル後の実行速度を必ず改善するわけではありません。
