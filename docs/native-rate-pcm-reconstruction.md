# 等速付近のPCM補間（r66）

modernプロファイルで、音程変更後に元波形の進行比が1へ戻った場合も、
小数の読み取り位置に対する補間精度を保持します。
従来は等速付近で線形補間へ切り替えていました。読み取り位置が半サンプルずれると、
同じ音程でも高い成分が大きく弱くなり、その状態が継続する場合がありました。

## 処理

- 進行比1・整数位置のサンプルは従来どおり元波形をそのまま使います。
- 進行比1・小数位置は32タップの全帯域補間を使います。
- 進行比0.8〜1で16タップから32タップへ滑らかに移行します。
- 1を超えたら32タップの低域通過処理へつなぎ、1〜1.1の線形補間へのフェードを除去します。
  1.1以上の既存の演算順、4倍以上の長いフィルターへの移行は保持します。
- 従来プロファイルは線形補間を維持します。発音の割り当て判断に渡す値も従来の
  線形サンプルを保持します。

サンプルの進む位置、音程、ゲート、EOF、ループ座標は変更しません。
録音Audio・ATRでは、新たに必要になる等速未満の32タップテーブルも発音準備時に用意します。
新しいフィルターバンクや音源ごとの永続メモリは増やしません。変換キャッシュはr66です。

## 検証

解析的な正弦波と比較する24,576位置の検査で、等速・小数位置の振幅を0.2%以内に
保持しました。従来プロファイルの全サンプルと、整数位置の等速サンプルは完全一致します。
0.8・1・1.1の切替境界、端点、短い波形も検査しています。
ループを繰り返した後に等速付近を行き来する検査を追加し、展開した元波形との
72,000サンプルの履歴比較を通過しました。

既存259素材はWAV全体が完全一致しました。新しい44素材では対象24素材だけが変わり、
20対照は完全一致しました。すべて形式・フレーム数を維持しています。
合計303素材中279素材が一致し、24素材だけが意図した変更です。

新素材は `tools/generate-unity-pcm-probes.py <新規ディレクトリ>` で再生成できます。
MA-7のPCM楽器、Mobile/MA-7の録音Audio、20ms後に音程を戻す楽器、
8・32サンプルの短いループ、整数位置の等速再生、適用範囲外の対照を含みます。
元波形は自作の正弦波で、メーカー音源や楽曲は使いません。

ASan/UBSan付きの音声回帰、高比率変換、録音Audio、ATR、PCM16出力ブリッジ、
入力保護の6スイートが通過しました。クラウドではリーク検査を無効にした
`ASAN_OPTIONS=detect_leaks=0`で実行しています。Android 3 ABIのDebug・Releaseと
lintも通過し、lintはエラー0件・既存警告4件です。

## ファイル全体の振幅測定

44.1kHzのPCM楽器を44.1kHzへ出力します。最初に+1半音で発音し、20ms後に
音程変更を0へ戻します。元波形の小数位置は保持されるため、これで約0.446サンプルの
ずれが残ります。30ms以降の2,048フレームを正弦・余弦に最小二乗で当てはめ、
最終PCM16 WAVの基音振幅を測ります。同じ音色を最初から等速で鳴らした値を1とします。

| 合成信号の周波数 | 修正前 | 修正後 |
| --- | ---: | ---: |
| 11,025Hz | 0.71100 | 0.99975 |
| 17,640Hz | 0.32543 | 0.99976 |

音程・位相に対応する振幅を保つ検査です。実曲全体の改善率、旧端末との音色一致や
すべての周波数での折り返し低減を示すものではありません。

## 負荷と限界

対象範囲の小数位置には、従来より多いタップを使います。通常の整数位置の等速再生は
高速経路を維持しますが、等速前後や音程を戻した後の変換処理量は増えます。
Android端末での処理時間・消費電力は未測定です。

ナイキスト周波数直近には有限長フィルターの遷移帯域が残ります。探索的な補間単体の
合成信号では、元波形0.499周期/サンプル・進行比1.01の条件で、出力RMS電力が線形混合を
使う従来処理より約0.6dB増える例もありました。この条件は後続の[r67](near-native-antialias.md)で
追加対策しました。上記はr66時点の記録です。
今回の採用理由は、等速付近の振幅・位相精度の改善と、適用範囲外の音声を保てることです。
