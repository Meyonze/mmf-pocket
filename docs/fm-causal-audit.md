# 変調FMの実時間向けフィルターを検証

`tools/fm-sideband-audit.cpp --causal-oversampling`は、2倍ずつ間引く
因果FIRを使った実験です。アプリの音声処理への組み込みは行いません。
既存の周期的・理想ローパスの実験と分け、有限長フィルターの誤差、固定遅延、
演算数、高音域の減衰、ステップ応答を測ります。

## 比較条件

- 出力44.1kHz。定常的な正弦波2演算器のPMを使います。フィードバック・4演算器・時間変化するEGは対象外です。
- ソフトウェアの互換／VM35プロファイル、倍率2:3・5:7・7:9、変調器TL0／24の12条件です。
- オーバーサンプリング倍率は2／4／8／16／32倍です。
- 各段31／63／127タップを使う3案と、前段31・最終段255タップの案を比較します。
- 最終カットオフは出力ナイキスト周波数の100%／95%。合計480実験と40種類のフィルター特性を出力します。
- Blackman窓の対称FIRです。半帯域のゼロ係数と対称ペアを利用し、毎サンプルの確保は行いません。
- フィルターのDCゲインだけを1に合わせます。除去した帯域の電力を戻す音量正規化は行いません。

## 数学上の基準と時刻

Jacobi–Anger展開の側帯波に、各段の密な周波数応答を掛けた基準と実際の
ストリーミング出力を照合します。初回480実験の最大RMS誤差は約1.33e-7でした。
これは既存ソフトウェアのPMモデルと有限FIRの計算を検証する値です。

`fir_equation_error_rms`は、その有限FIRが予測どおり動くかを示します。
`aligned_band_error_rms`は、出力ナイキスト未満の側帯波だけを残す理想基準との誤差です。
後者だけは、報告した群遅延を基準側で合わせ、単なる時刻のずれを誤差から除きます。
実際のストリームは過去の入力だけを使い、先読みや時刻補償を行いません。

冒頭256出力フレームは定常測定のために除外します。これはフィルターの遅延値ではありません。
`group_delay_frames/ms`がフィルターの群遅延、`support_bound_frames`が係数の時間範囲の上限です。
アプリ全体の再生遅延・端末負荷・消費電力を測った値ではありません。

自己検証は全入力位相のインパルスを密な畳み込みと照合し、DC・対称性・周波数応答・
ステップの収束・未来の入力を変えても過去の出力が変わらないことを確認します。
CLIは遅延と演算数を各段のレートから独立に再計算し、既存の96条件も保護します。

## 結果から分かったこと

8倍・100%カットオフの例では、全段127タップは出力1フレーム当たり224乗算、
前段31・最終段255タップは112乗算です。後者の群遅延は約1.57msです。
VM35・倍率2:3・TL24の理想帯域基準との誤差は、約0.01176から0.00109になりました。
乗算数はフィルター部分だけの値で、8倍のFM合成そのものの処理は別に必要です。

同じ前段31・最終段255タップでも、VM35・5:7・TL0は8倍で約0.230、32倍で約1.26e-5です。
有限フィルターの境界漏れと、合成時点ですでに折り返した成分を分けて検討する必要があります。

95%へのカットオフ変更は、不要成分を減らすケースと、必要な高音を減衰させるケースがあります。
1／20／21.8／24kHzの応答と、ステップのオーバーシュート／アンダーシュートも報告します。
低い誤差だけを理由に一つの設定を全音色へ適用する段階ではありません。

次は他パートとの遅延の統一、発音・ゲート・シーク・末尾の状態、変化するEG、
4演算器／フィードバック、対象を限定した負荷測定が必要です。
この実験はメーカーのチップや内蔵ROMを校正したものではありません。

## 実行

```sh
c++ -std=c++20 -O2 -Ithird_party/yamaha-smaf-player/src tools/fm-sideband-audit.cpp build/native-render/libsmaf.a -o build/fm-causal-audit/audit
build/fm-causal-audit/audit --self-test
build/fm-causal-audit/audit --causal-oversampling > build/fm-causal-audit/causal.json
python3 tools/fm-sideband-audit-cli-test.py --binary build/fm-causal-audit/audit
```

`--oversampling`は従来の理想ローパス実験のままです。標準レポートと理想実験の既存96行の
数値は変更前と完全一致しています。アプリ、正式版、変換キャッシュは変更しません。

続く[整数遅延とネイティブ時刻の試作](fm-aligned-prototype.md)では、限定した2演算器の
EG・LFO更新を保ち、PCMとの群遅延統一、Hold・再発音・末尾・全体リセットを検証しています。
