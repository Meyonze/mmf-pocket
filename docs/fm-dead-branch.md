# 音声を変えずに、使われないFM途中計算を省く

接続3・4の限定した追加サンプル生成で、読み手が既にスキップされる演算器の
上流を計算しないようにしました。元のnative tickは全演算器を一度ずつ進めます。

| 接続 | 省ける途中計算 | 条件 |
| --- | --- | --- |
| 3 | op1 | 唯一の読み手op2が途中サンプルでスキップされる |
| 4 | op0 | 唯一の読み手op1が途中サンプルでスキップされる |

これらの接続の適用条件は[r87〜r89](fm-reduced-graphs.md)を維持します。
単にEGのレベルが0かどうかで省略しません。EVBによって停止した枝も波形計算を
実行する場合は、符号付きゼロを経由する元の計算を保ちます。途中サンプルの省略であり、
位相・EG・LFO・発音枠・発音終了・元のサンプル終点は変えません。

## 一致と処理時間

変更前のライブラリを保存し、接続0/3/4/5/6/7、二つのサンプルレート、三つの形式、
2/4/8/16/32倍、Exact/Hermite、EVB・低位アタック・微小音・音程変更・Hold・再発音を
含む1,440条件で比較しました。4,571,136個のfloatとフレームごとの発音状態を
バイナリ記録し、符号付きゼロも含めて完全一致しました。
既存の接続0/5/7も対照に含みます。通常の音声キャッシュはr89を維持します。

共有Linuxホストの同じCPUに処理を固定し、前後の実行順を交互にした7組の中央値です。
32音・8,192フレーム、Hermite、停止したゲートのEVBなしという条件です。

| 接続 | 8倍での合成CPU時間の短縮 | 16倍での短縮 |
| --- | ---: | ---: |
| 3 | 約7.6% | 約9.7% |
| 4 | 約10.8% | 約18.2% |

対象外やEVBで省略できない対照条件の前後比は、全条件の中央値で約1.006でした。
個別条件には数%のばらつきがあり、共有ホストの小さな差を速度改善の根拠にはしません。
この測定はFM合成部分だけで、FIR・ミックス・入出力を含むアプリ全体の値ではありません。
Android端末上の速度・消費電力は未測定です。

既存の数式基準、短音、混在、パート寄与の検査を維持し、停止ゲートのEVB有無を含む
発音時計の検査を360条件へ広げています。正式版は1.6.6のままです。

## r90の共通位置計算と演算器ごとの並べ替え

追加サンプルの倍率2/4/8/16/32はすべて2の累乗です。`inc * sub`の順序を維持したまま、
その後の除算を、フレームごとに一度求めた正確な逆数の乗算へ置き換えました。
通常とFMA有効のそれぞれで、1,440条件の音声・発音状態を変更前とバイナリ比較しています。

対応する接続0/3/4/5/6/7のHermiteでは、同じ演算器の独立した途中サンプルを先に作り、次の演算器へ渡します。
各点の演算・丸め順とnative tickは保ち、512byteの固定作業領域をスタックに使います。
必要なセルはすべて書き、スキップされる行の正のゼロも明示します。ヒープ領域は追加しません。
Exact方式は従来の点ごとの計算を保ちます。

7組のピン留め・交互順の32音16倍ソース比較では、共通位置計算で約5〜8%、
接続6の並べ替えでさらに約37%のCPU時間短縮を観測しました。後者の接続7対照はほぼ同じでした。
音声・実ファイルWAVは同じで、アプリ全体・Android端末の速度を表すものではありません。
[適用範囲と数値](fm-weak-nested-r90.md)を参照してください。

接続6で確認した並べ替えを、同じ算術順を保って他の対応接続にも適用しました。
接続6のみ並べ替えた版を基準とする、7組の交互順・同一CPUでの追加測定では、
接続0/3/4/5/7の8倍・16倍の中央値でCPU時間が約9〜45%減りました。
停止ゲートのEVB有無も含む24条件で、接続6の比率は0.984〜1.031でした。
測定は共有Linuxホスト上の合成部分だけで、実機の速度・消費電力の測定ではありません。
