# 高倍率FMの除算を同じ結果のまま軽量化

実験用の16/32/64/128倍の直列FMで、サンプルごとに繰り返していた位相の除算を軽量化しました。
通常アプリの倍率方針・音量・キャッシュr91・正式版1.6.6は維持しています。

## 計算と適用条件

倍率は2のべき乗なので、逆数を一回計算して乗算に使えます。
各演算器の絶対位相増分が`DBL_MIN * factor`以上、`DBL_MAX / factor`以下の場合に使います。
この範囲では、`inc * sub`が有限の正規数で、その結果を倍率で縮めても正規数に収まります。
2のべき乗による縮小は仮数を丸めないため、元の除算と同じ結果になります。
外側の加算とFMAで融合しても、掛ける値が正確なので元の値を維持します。
通常の再結合を許さないビルド設定が前提です。

`(inc * sub) * inverseFactor`の順序を維持します。
先に`inc`を縮めてから`sub`を掛けると、加算とのFMA融合で丸める位置が変わり得ます。
ゼロ・極小値・過大な値・非有限値では元の除算式を使います。
拡張精度を使う`FLT_EVAL_METHOD != 0`の構成では元のループ全体を残します。
条件の判定をサンプルのループ外へ移し、通常の乗算経路に毎回の分岐を加えません。
回転用のステップも、同じ安全な範囲で乗算に置き換えます。

補間の式・精度・中間行の配置は維持します。
native終点、EG・LFO・Hold・発音枠、倍率選択、音量、FIR、PCM/録音Audio/ATRの経路も維持します。

## 確認と測定範囲

- 10,368条件・622,080サンプルを、元の除算による参照レンダラーと照合しました。
  VM35/MA7、Exact/Hermite、4種類の丸めモードと、ゼロ・正規/非正規・巨大値・非有限の境界を含みます。
- 別のコンパイラー文脈では下向き丸め時のゼロの符号が旧実装でも異なるため、参照式との比較はその差を除きます。
  変更前の音源を別にコンパイルした比較では、ゼロの符号も含めて一致を確認しています。
- GCC/ClangのFMAを含む標準・融合なし・融合fastの各設定と、x87の旧経路を検査しています。
- 既存のコア出力・発音時計・独立波形モデル・曲末・シーク・混在再生の検査も使います。

共有LinuxホストでCPUを固定し、実`MaPlayer`を変更前後で9回交互に測定しました。
VM35接続6、32音、固定64/128倍とビブラート有無の4構成では、CPU時間が約4〜17%減りました。
出力floatのハッシュも一致しています。通常経路の対照測定にもぶれがあり、全構成での高速化を示す結果ではありません。
測定には音源・混合・FIR・LP・リミッターを含み、初期化・JNI・ファイル入出力は含めません。
Android端末上の速度・消費電力は未測定です。
