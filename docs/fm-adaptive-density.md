# r85：必要な正弦波FMだけ16倍へ切り替える

通常再生・WAV保存の正弦波FM処理を、固定8倍から「8倍を基本とし、側帯波が広がる音だけ
16倍」へ進めます。対象接続は0・5・7の正弦波・実効フィードバックなしに限定します。
音量を正規化せず、発音枠・EG・LFO・nativeサンプル終点は維持します。変換キャッシュはr85です。
正式版1.6.6の更新・公開はまだ行っていません。

## 密度の選択

各PM枝について、現在の位相増分、ビブラートの最大幅、変調器のTL/KSLとPM深度から、
凍結した定常PMモデルの側帯波尾部を見積もります。EG/AMは最大値で扱い、現在たまたま
小さい音だからといって低い倍率を選ぶことはしません。floatへの丸めも上側に見込みます。

βを変調指数とすると、Bessel係数は次で上から押さえられます。

```text
|J_n(β)| <= (β/2)^n / n! * exp(β² / (4(n+1)))
r = β / (2(n+1)) < 1 のとき、両側の尾部 <= 2 * 上記の項 / (1-r)
```

8倍で元の出力帯域±0.5へ折り返す可能性のある範囲は、8±0.5以降です。
単に8倍のNyquist=4を越えた側帯波が、すべて最終出力へ残るわけではありません。
その範囲に入る次数からの尾部上限が1e-4を超える音を16倍へ回します。
1e-4はこの定常モデルの係数尾部の予算であり、無音の打ち切り値ではありません。
時間変化するEG/LFOや有限FIRも含めた、全出力の誤差上限を保証するものではありません。
16倍でも足りない条件は残り、一律の最適倍率を決めたわけではありません。

計算は音符・音程・ビブラート倍率の変更に対応してキャッシュします。同じ音符の途中では
8倍から16倍へ上げるだけにし、下げません。再発音時は判定をやり直します。
永久に無音の変調器や対象外の接続は除外し、MA7の低位アタックビットは保持します。

## 二つの経路と時刻

8倍・16倍それぞれの共有FIRを持ち、どちらも72フレームの遅延に揃えます。
PCM・録音Audio・独立ATR・対象外FMのnative FIFOは一つだけです。
二つのFM出力とnative出力を足してから、既存のローパス・リミッター・携帯風処理を適用します。
切り替え前の8倍FIRは余韻を流しながら、新しい入力を16倍へ渡します。
16倍の入力がなくなり有限の支持長を流し終えた経路は休止します。
両方の経路とnative FIFOを流し終えるまで自然終了せず、シークは全履歴をリセットします。

開発用APIでは以下で明示できます。固定倍率・CLIの既定は維持します。

```cpp
player.init(file, 44100, false, {8, FmSubframeMath::Hermite, true});
```

`boostHighNotes=true`は基準倍率8の場合だけ有効です。パート寄与診断も
`--app-quality`で自動密度を扱い、8倍・16倍の使用量と混在出力を測れます。
[集計方法と適用範囲](render-contributions.md)を参照してください。
アプリの倍率設定画面は追加していません。

r90ではこの方針に[弱いVM35接続6の固定16倍](fm-weak-nested-r90.md)も含めます。
直列3演算器へ単一PM対の尾部推定は流用せず、この追加範囲は音程にかかわらず16倍です。

## 検証と改善例

独立したBessel係数の絶対値和を112条件で尾部上限と照合しました。
公開プレイヤーの48条件では2条件だけが16倍となり、46条件は8倍を維持しました。
有限FIR・ローパスを含む独立モデルとの最大RMS誤差は約2.99e-8です。

音程96・キャリア5・変調器7・TL0の定常例では、理想帯域とのRMS誤差が以下へ低下しました。

| 接続 | 固定8倍 | 選択的16倍 |
| --- | ---: | ---: |
| 0 | 0.0969059 | 0.00000849283 |
| 7 | 0.0387624 | 0.00000309023 |

900フレームのPCM/8倍/16倍混在を、別計算の密なFIR畳み込みと比較しました。
途中で音程を上げて戻す、再発音、Hold、停止を含めて一致し、通常のC++ `new`は0回でした。
最後の一フレームだけの高い音の余韻、1/17/512/1024フレーム、シーク、無効な設定も検査します。
ReleaseとASan/UBSanで通過しています。既存の固定倍率・native検査も維持します。

実アプリWAVの32素材では、対象の高音域一素材が明示16倍処理と一致し、31素材はr84と
完全一致しました。従来の非FM素材と低い音も一致します。強い高音域の接続0/7を実JNI/WAV検査へ
追加し、携帯風の有無、小音量、EOF、書き込み失敗も確認しています。
Android全ABIのDebug/ReleaseビルドとLintが成功しました。

## 処理量の参考

共有ホストで32音を一秒合成した3回の中央値です。16倍に回す音数も実際の判定値と照合しています。

| 16倍が必要な音数 | 固定8倍 | 固定16倍 | 選択式 |
| --- | ---: | ---: | ---: |
| 0 | 410ms | 728ms | 412ms |
| 1 | 400ms | 682ms | 426ms |
| 8 | 397ms | 726ms | 698ms |
| 32 | 509ms | 1,012ms | 836ms |

共有ホストでは測定値が大きく変動し、小さな差や全音16倍での逆転は性能向上の根拠にしません。
目的は必要な音だけ演算を増やすことで、Android上の速度・消費電力は未測定です。

追加の2,153入力を同じ時間上限でアプリ初期化と固定8倍へ渡し、全件でnativeの位相・EG・LFO・
PCM位置・発音枠履歴・音源割り当てカウンターが一致しました。2,152件は出力もビット単位で一致し、
変わった一件は意図した高音域の比較素材でした。二件は時間上限までの検査です。
NDK ClangをLinuxホスト向けにした実行でも、上記のモデル・混在・終端検査を通過しました。
これはAndroid実機での実行ではありません。

尾部の実装は階乗にRobbinsの下界を使い、ガンマ関数の共有符号状態に依存しません。

## r86：Nyquist境界を含める

側帯波が8±0.5の境界に正確に一致する場合も尾部の最初の次数に含めるよう、
切り上げで求めます。従来の`floor(x)+1`は整数の場合だけ境界の係数を外していました。
β=8π、キャリア0.109375、変調器0.171875の厳密な二進数の対照で修正前の失敗と
修正後の成功を確認しました。既存48条件の選択と改善値は維持し、キャッシュはr86へ更新します。

## アタックと短い音の保護

定常側帯波の尾部上限だけでは、アタックやゲート終了付近の時間波形の差を保証できません。
定常時の上限を狭めて8倍へ回す試案は、開始・終了付近に差が出たため採用していません。
この試案は判定・キャッシュr86へ反映していません。後続のr87はこの上限を維持したまま、
[無音の枝で簡約できる接続](fm-reduced-graphs.md)へ適用範囲を広げます。

接続0/7・音程85/86・ゲート長1/44/441フレーム・通常NoteOff/AllSoundOffの
24条件を公開プレイヤーで比較し、独立した固定16倍の参照に対してピーク差1e-5未満、
RMS差1e-6未満を要求する回帰検査を追加しました。定常時の検査に加えて、
今後の密度選択変更がこの範囲の発音開始・終了を損なわないことを確認します。
これは全音色の誤差保証や実機との一致を示すものではありません。


R91 adds [coherent MA7 nested graph6](fm-ma7-nested-r91.md) without fixed frequency
or detune. Like weak VM35 nested6, it selects16 at every pitch and does not use
