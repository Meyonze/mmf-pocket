# 無音音符と同時発音数（r68）

MA-7のVelocity 1とSP-MIDIバンク121/6は常に無音として扱っています。
従来は音量をゼロにするだけで、FM/PCMの発音枠を割り当てていました。
既に32音を保持している状態では、無音音符が鳴っている音を奪い、パートの音が
欠落する場合がありました。次の発音で置き換える枠の順番にも影響します。

## 修正

この2種類は音色の解決・代替音色の選択・発音枠の割り当てより前に処理を終了します。
音符のデコードやゲート、曲末の時刻は変更しません。
`MaPlayer::Diagnostics::suppressedSilentNotes`で実行時の省略数を数えます。
音色調査ツールの論理音符数と`immutable_silent`の分類は保ち、
実際には割り当てないFM/PCMの発音数は増やしません。

チャンネル音量やExpressionがゼロの通常音符は、その後の操作で聞こえる可能性があるため、
引き続き発音枠を割り当てます。Mobile/HandyPhoneのVelocity 1も従来どおり扱います。
楽器別の音量、FM/PCMの比率、代替音色の音量・余韻は調整していません。
変換キャッシュはr68です。

## 再現と検査

`tools/silent-note-pool-test.cpp`は、自作のFM/PCM持続音を32音鳴らし、
別チャンネルに無音音符を加えます。無音音符だけを除いた対照スコアと、
最終ステレオ波形がサンプル単位で一致することを確認します。
修正前のr67では、この一致検査が失敗しました。

96条件で、2種類の無音指定、チャンネル1/17、明示・省略Velocity、後続の有音音符、
1/257/1024フレームの分割を検査します。シーク後の一致と診断値の初期化、
通常の音量・Expressionを後から上げる4条件も確認します。
CIのネイティブ検証にも追加しています。

既存の自作357素材もr67と比較し、WAV全体がすべて一致しました。
これらは今回の発音枠不足を再現しない対照素材であり、修正の効果は上記の
32音同時発音テストで確認しています。音色調査CLIの9検査も通過しました。

Androidの3 ABIのDebug・Releaseビルドとlintも通過しています。
lintはエラー0件・既存警告4件です。

ASan/UBSan付きで、音声回帰、無音音符の同時発音、音色調査、PCM16出力ブリッジ、
入力保護の5スイートの全範囲を確認しました。音声回帰は通過済みの前半24項目と、
旧仕様の期待値を更新して再実行した後半を合わせた検証です。本体コードは途中で変更していません。
クラウドでは`ASAN_OPTIONS=detect_leaks=0`でリーク検査を無効にし、
アドレスと未定義動作の検査を実施しています。

## 残る範囲

今回の修正が効くのは、対象の無音音符が同時発音枠を消費するケースです。
ユーザーが気になった個別曲の原因を確定したものではありません。
端末ROMの代替音色や、埋め込みFMとPCMの音量校正には引き続き比較音源が必要です。
