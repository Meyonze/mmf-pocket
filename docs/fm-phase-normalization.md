# FMの位相計算を同じ結果のまま軽量化

FM演算器で、範囲が分かっている位相の正規化を短縮しました。
通常アプリの再生方式・音量・キャッシュr91・正式版1.6.6は維持しています。

- 波形を読む位相が厳密に0より大きく1より小さい場合、`floor`の結果はゼロなので、そのまま使います。
- 位相を進めた結果が1以上2未満の場合、`floor`の結果は1なので、1を引きます。
- ゼロ、負の位相、境界、大きいジャンプ、非有限値では従来の正規化を残します。
  ゼロを通常範囲に含めないため、符号付きゼロと丸めモードの挙動も維持します。

演算器の処理だけを変更し、倍率の方針やFIR、EG、LFO、発音枠は変えません。
高倍率の中間行の配置や、補間方式・波形の近似精度も維持しています。

## 確認と負荷

位相時計の1,152条件を、元の`floor`による計算と4種類の丸めモードでビット単位に照合します。
既存の波形境界・符号付きゼロ・非有限入力・ピッチ復帰のテストも使います。
変更前のライブラリとの波形照合では、全波形と別名番号を含む約292万サンプルと位相状態が一致しました。
通常・固定高倍率・自動倍率の実プレイヤーについても、保存済みの入力でPCMと発音時計を照合します。

共有Linuxホストで、変更前後を同一CPUへ固定し、1・8・32音、ビブラート有無、通常・自動・固定128倍を
9回交互に測定しました。音源・混合・FIR・LP・リミッターを含む実`MaPlayer`の処理時間です。
このVM35接続6の測定音色は、従来方式ではnative処理になるものです。通常32音のCPU時間が
ビブラートなしで約9%、ありで約10%減りました。
自動倍率・固定128倍では改善が小さく、全構成での高速化を示す測定ではありません。
Android端末上の速度・電力の測定ではなく、初期化・JNI・ファイル入出力も測定に含めていません。
