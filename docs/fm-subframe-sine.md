# 追加サンプルだけの正弦波計算を軽量化

2演算器と[並列4演算器](fm-parallel-pair-prototype.md)のホスト試作に、明示的に選ぶ
`frameFast()`を追加しました。従来の`frame()`は`std::sin`のままです。
アプリの音声処理、公開版1.6.6、変換キャッシュr82は変更しません。

## 保持する計算

どちらの方式でも、元の`FmVoice::tick()`をネイティブフレームにつき1回呼びます。
EG・LFO・Hold・解放状態・発音枠の音量評価を保ち、最終サンプルには元の出力を使います。
終点の独立した再構成も`std::sin`で行います。軽量化するのは、追加する途中の正弦波だけです。
フィードバックや直列4演算器、他の波形へは使いません。

## 補間の誤差

`tools/fm-subframe-sine.h`は、256区間の正弦と傾きを使う3次Hermite補間です。
係数は全音源で共通の8,192 bytesで、初回に準備します。毎フレームの確保はありません。
入力が既に0〜1周期に収まっている場合は、余分な周期の除去も省きます。
範囲外は従来と同じ周期へ折り返し、非有限値を配列の添字に変換しません。

区間幅をh=2π/256とすると、正弦波の補間誤差はh^4/384で上から抑えられます。
約104万点の照合では最大約9.44912e-10で、数式上の約9.44993e-10の範囲でした。
区間の値・傾きと周期境界も照合しています。この値は正弦の補間単体の誤差です。

FMでは演算器のfloat丸めや変調を通すため、別に比較しています。
2演算器・並列4演算器それぞれ480条件・4,571,136サブサンプルで、
元の計算との差は次のとおりでした。これらは検証した条件の観測値です。

| 対象 | 最大絶対差 | RMS差 |
| --- | --- | --- |
| 2演算器 | 約1.06e-7 | 約6.69e-10 |
| 並列4演算器 | 約5.96e-8 | 約5.37e-10 |

ネイティブの出力と状態は両方式で一致しています。音程変更・ナイキスト超過・音量ゼロと復帰、
AM/VIB・Hold・解放・再発音も含みます。近似誤差を次のフレームの状態へ蓄積する処理ではありません。

## フィルターと混在

- `std::sin`方式と補間方式を含む40条件の因果FIR出力を、各側帯波と複素周波数応答から求めた基準と照合。
  最大RMS誤差は約8.99e-8でした。音量補正は加えません。
- 混在の14,400出力と、両方式の実FM・PCM・独立入力の7,200出力を照合。
  停止・再発音・適用対象の切り替え・シーク・EOFを含みます。
- 従来方式の側帯波レポートは、既存96条件と因果FIR60条件を含む全項目が変更前と一致。
- 補間・状態・波形・混在のテストをRelease O2とASan/UBSanで確認。既定レポートの変更前後の比較はReleaseで確認。

## 負荷の比較

`fm-render-prototype-cost`は、二つの方式を交互の順番で測定します。
共有ホスト、各3回、2,048フレームの試作全体で、FM合成・PCM・独立入力を含みます。
初期化・係数準備・ファイル入出力は除き、診断用の終点再構成は含みます。

| 8声・32倍 | 従来方式の中央値 | 補間方式の中央値 |
| --- | --- | --- |
| 2演算器 | 約50.5ms | 約28.7ms |
| 並列4演算器 | 約74.6ms | 約44.5ms |

216回の測定でフレーム処理中の通常のC++ `new`は0回でした。共有テーブル8KiBは別に存在します。
短い共有ホスト測定なので、端末の速度や電力削減率、実曲すべてでの改善を保証する値ではありません。
32声など重い条件と、Androidでの負荷は引き続き確認が必要です。

```sh
mkdir -p build/fm-subframe-sine
c++ -std=c++20 -O2 tools/fm-subframe-sine-test.cpp -o build/fm-subframe-sine/test
build/fm-subframe-sine/test
c++ -std=c++20 -O2 -Ithird_party/yamaha-smaf-player/src tools/fm-render-prototype-cost.cpp build/native-render/libsmaf.a -o build/fm-subframe-sine/cost
build/fm-subframe-sine/cost > build/fm-subframe-sine/cost.json
```

対象と倍率の選択、停止方針、本体イベント・共有出力処理・WAVの先頭と末尾との接続は、
この計算の軽量化とは別に検証します。既定の計算方式は自動で置き換えません。
